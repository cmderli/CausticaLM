# NRD (Real-time Denoisers) → Java + Vulkan integration specification

## 0.1 Executive summary (the five facts that shape the whole design)

1. **NRD 4.17 makes no graphics-API calls and has no pipeline-creation callback.** `README.md:137`: *"NRD doesn't make any GAPI calls. The application is supposed to invoke a set of compute Dispatch calls to do denoising."* The host (our shim) receives POD descriptions — including compile-time-embedded SPIR-V bytecode — and creates `VkShaderModule`/`VkPipeline`/`VkDescriptorSetLayout`/UBO/descriptor sets itself. There is **no** `MessageCallback`, no log callback, no device/allocator callback, and no `ComputePipelineDesc → VkPipeline` callback anywhere in the 4.17 headers (the only callback type in the SDK is `nrd::AllocationCallbacks`, `NRDDescs.h:375-381`).
2. **The SPIR-V is embedded inside the NRD library**, not shipped as files. Option `NRD_EMBEDS_SPIRV_SHADERS` default `ON` (`CMakeLists.txt:21`); `PipelineDesc::computeShaderSPIRV.bytecode` points into the library's copy of the generated `*.cs.spirv.h` blob tables.
3. **The Vulkan binding contract is fixed and tiny**: 2 descriptor sets, spaces 0 (resources) and 1 (CB + samplers), binding numbers derived from `LibraryDesc::spirvBindingOffsets`, **no push constants**. The constant data goes through a uniform buffer at set 1 / binding 2.
4. **The shim only has to bind 3 non-optional guide textures, 2 packed noisy inputs, and 2 outputs** for `REBLUR_DIFFUSE_SPECULAR` (`IN_MV`, `IN_NORMAL_ROUGHNESS`, `IN_VIEWZ`, `IN_DIFF_RADIANCE_HITDIST`, `IN_SPEC_RADIANCE_HITDIST`, `OUT_DIFF_RADIANCE_HITDIST`, `OUT_SPEC_RADIANCE_HITDIST`). Albedo, specular albedo and specular motion vectors are **not** NRD inputs (§4.5).
5. **Licensing is the biggest non-technical risk**: the NRD SDK is *not* open source (NVIDIA RTX SDKs license) and clause 4(e) forbids using it in a way that puts it under an open-source license. This repository is LGPL-3.0-or-later. See §9 for the compliant pattern (fetch at build time, ship object code only).

`Result` (`NRDDescs.h:24-33`): `SUCCESS`, `FAILURE`, `INVALID_ARGUMENT`, `UNSUPPORTED`, `NON_UNIQUE_IDENTIFIER`.

### 2.2 What the shim must supply at create time

`InstanceCreationDesc` (`NRDDescs.h:409-414`) is only:

```cpp
struct InstanceCreationDesc {
    AllocationCallbacks allocationCallbacks;   // CPU allocator, NOT a GPU allocator
    const DenoiserDesc* denoisers;             // { Identifier identifier; Denoiser denoiser; }
    uint32_t denoisersNum;
};
```

* **Device / queue / instance**: nothing. There is no `VkDevice` in any NRD desc. NRD never touches Vulkan (`README.md:137`).
* **`AllocationCallbacks`** (`NRDDescs.h:375-381`): `void*(NRD_CALL*Allocate)(void* userArg, size_t size, size_t alignment)`, `Reallocate`, `Free`, `void* userArg`. All three are **CPU** allocators. If *any* of the three pointers is null NRD substitutes its own aligned `malloc/realloc/free` trio (`Source/Wrapper.cpp:186-192`, defaults at :119-178); the check is `!Allocate || !Reallocate || !Free`, so a partially-filled struct is silently replaced. Passing `{}` (as the official Vulkan sample does) is fine.
* **Denoiser list**: one `DenoiserDesc` per denoiser *instance*. Each `identifier` must be unique across the instance, else `Create` returns `NON_UNIQUE_IDENTIFIER` (`Source/InstanceImpl.cpp:104-108`); a `Denoiser` not in `LibraryDesc::supportedDenoisers` returns `UNSUPPORTED` (:95-102). One identifier = one denoiser instance with its own history and its own `SetDenoiserSettings` slot.
* **No `MessageCallback`**: the type does not exist in 4.17. NRD has no logging/validation callback. (The official *sample* implements its own debug overlay via the `OUT_VALIDATION` resource, `README.md:533-564`; the "debug" NRD build it mentions at `README.md:793` refers to the NRD-Sample repo, not to an SDK callback.)
* **No shader-blob selection at create time**: blob selection happens when you walk `InstanceDesc::pipelines[i]` (§3.1).

### 2.3 What NRD returns

`GetLibraryDesc()` (a process-wide singleton, `Source/Wrapper.cpp:43-51`) gives:

```cpp

    const Denoiser* supportedDenoisers; uint32_t supportedDenoisersNum;

```

Concrete values for a stock v4.17.3 build (`Source/Wrapper.cpp:44` + `CMakeLists.txt:88-91`):

```cpp

normalEncoding      = (NormalEncoding)NRD_NORMAL_ENCODING;   // default 2 = R10_G10_B10_A2_UNORM

```

**Vulkan-specific caution (`README.md:129`)**: *"This call can be skipped if this information is known in advance … but it can't be skipped if SPIRV binding offsets are needed for Vulkan."* Read them at runtime; do not hardcode 0/2/3/20.

`GetInstanceDesc(instance)` returns NRD-owned memory valid for the instance lifetime (`Source/Wrapper.cpp:208-210`) and is what the shim turns into Vulkan objects. `PrepareDesc()` (`Source/InstanceImpl.cpp:630-705`) fills: space indices, register indices, samplers, entry point, pipelines, permanent/transient pools, descriptor-pool limits. The values are compile-time constants from the shader side (`Shaders/NRD.hlsli:81-90`):

| `InstanceDesc` field | Value | Source |
|---|---|---|
| `constantBufferAndSamplersSpaceIndex` | `1` | `NRD.hlsli:85` |
| `resourcesSpaceIndex` | `0` | `NRD.hlsli:84` |
| `constantBufferRegisterIndex` | `0` | `NRD.hlsli:81` |
| `samplersBaseRegisterIndex` | `0` | `InstanceImpl.cpp:639` |
| `resourcesBaseRegisterIndex` | `0` | `InstanceImpl.cpp:644` |
| `shaderEntryPoint` | `"main"` | `InstanceImpl.cpp:641` (`NRD_STRINGIFY(NRD_CS_MAIN)`, `NRD.hlsli:88-90`) |
| `samplers` / `samplersNum` | `{NEAREST_CLAMP, LINEAR_CLAMP}` / `2` | `InstanceImpl.cpp:13-16, 637-638` |
| `constantBufferMaxDataSize` | max `constantBufferDataSize` over unique passes (≈0.9 KB for REBLUR/RELAX radiance mode) | `InstanceImpl.cpp:689` |
| `descriptorPoolDesc` | see §3.5 | `InstanceImpl.cpp:652-698` |

**Resize**: NRD has no resize (`README.md:139`: *"NRD doesn't have a 'resize' functionality. On a resolution change the old denoiser needs to be destroyed and a new one needs to be created"*). Destroy + recreate on render-size change. Dynamic resolution scaling is supported through `CommonSettings::resourceSize/rectSize` (§5.1) but the *pools* are sized from them.

**Threading**: the API is not documented as thread-safe. The integration layer is explicit — `Integration/NRDIntegration.h:210`: `// Threadsafe: no`. Additionally `GetComputeDispatches` returns pointers into instance-owned scratch memory that is invalidated by the next call (`NRD.h:65`). Use one `nrd::Instance` per thread; never call two functions on one instance concurrently.

### 2.4 Cheap version check the shim must do

`Integration/NRDIntegration.hpp:19` does `static_assert(NRD_VERSION_MAJOR >= 4 && NRD_VERSION_MINOR >= 17, ...)`, and :126-130 compares `LibraryDesc::versionMajor/Minor` against the header's macros. The shim should do the same at create time and also compare `versionBuild` against `NRD_VERSION_BUILD`, because `SetDenoiserSettings` `memcpy`s `sizeof(ReblurSettings)` bytes (`Source/InstanceImpl.cpp:456-459`) — a header/library mismatch silently corrupts settings.

## 3. Pipeline creation

### 3.1 Answer: (b) the host creates pipelines from NRD-provided bytecode

There is **no** pipeline callback in NRD 4.17. NRD returns, per pipeline, a `PipelineDesc` containing the compiled bytecode for each supported backend plus the resource-range layout; the host creates `VkPipeline` objects. Then, per frame, NRD returns a list of `DispatchDesc`, each of which names a `pipelineIndex` into that array. The host binds *its own* pipeline for that index and records a `vkCmdDispatch`.

```cpp
struct ComputeShaderDesc { const void* bytecode; uint64_t size; };      // NRDDescs.h:435-439

struct PipelineDesc {                                                    // NRDDescs.h:441-454
    ComputeShaderDesc computeShaderDXBC;
    ComputeShaderDesc computeShaderDXIL;
    ComputeShaderDesc computeShaderSPIRV;   // <-- Vulkan uses this one
    const ResourceRangeDesc* resourceRanges;
    uint32_t resourceRangesNum;             // up to 2: TEXTURE inputs (optional) then STORAGE_TEXTURE outputs
    bool hasConstantData;                   // hint: pipeline has a cbuffer with InstanceDesc constants
    char shaderIdentifier[256];             // "File.cs.hlsl|MACRO=value|..." — informational
};
```

How each field must be handled by the shim:

| Field | What the shim does |
|---|---|
| `computeShaderSPIRV.bytecode/size` | `vkCreateShaderModule` with `codeSize = size` (must be a multiple of 4; the sample divides by 4 to make a `uint32_t` view). Never `free()` it: it points into NRD's embedded blob. |
| `computeShaderDXBC` / `computeShaderDXIL` | Ignore on Vulkan (null in a SPIR-V-only build; the blobs are `#include`d only when the corresponding `NRD_EMBEDS_*` macro is 1, `Source/Reblur.cpp:397-434`). |
| `resourceRanges` / `resourceRangesNum` | Drives the per-dispatch descriptor writes: range 0 is `DescriptorType::TEXTURE` (SRV) and range 1 is `STORAGE_TEXTURE` (UAV); a range is **omitted** when its descriptor count is 0 (`Source/InstanceImpl.cpp:596-611`). Consequence: `resourceRangesNum == 1` means "storage-only" (that is what the clear passes look like), which is the invariant behind `NRDIntegration.hpp:840`. |
| `hasConstantData` | `false` only for the two `Clear` pipelines (`AddDispatchNoConstants` passes size 0, `Source/InstanceImpl.h:95-106`; `hasConstantData = constantBufferDataSize != 0`, `InstanceImpl.cpp:595`). The clear shaders still *declare* a cbuffer block (`Shaders/Clear.resources.hlsli:13-17`) though they do not read it. **Always bind a valid UBO anyway** — that is what NRD's own integration does unconditionally (`NRDIntegration.hpp:852`). |
| `shaderIdentifier` | Log it; useful for debugging which permutation failed to compile. Not needed at runtime. |
| `pipelinesNum` | Deduplicated by SPIR-V bytecode pointer (`InstanceImpl.cpp:576-592`), so permutation loops collapse: `REBLUR_DIFFUSE_SPECULAR` = 12 pipelines, `RELAX_DIFFUSE_SPECULAR` = 13, `REFERENCE` = 2, `Clear (f)`/`Clear (ui)` = 2 → **29** for an instance holding REBLUR + RELAX + one REFERENCE (a second `REFERENCE` identifier adds none). The official sample logs each one at construction (`nrd_wrapper.cpp:460`), so the true number is observable at runtime. |

**Consequence of dedup (a real trap):** one `VkPipeline` is shared by several dispatch permutations (e.g. RELAX A-trous ping vs pong vs final `OUT_*`, or REBLUR temporal accumulation with/without confidence inputs). Such dispatches agree only on the *number and type* of descriptors, not on which `ResourceType` fills each slot. Therefore: read the descriptor-set-layout shape from the **pipeline's** `resourceRanges`, but fill the descriptors from the **dispatch's** `resources[]` names (the sample only asserts the descriptor type matches, `nrd_wrapper.cpp:616`).

**Blob selection proof** (for Vulkan, `computeShaderSPIRV`): `NRDIntegration.hpp:213` indexes the three shader descs as an array with `[std::max((int32_t)deviceDesc.graphicsAPI - 1, 0)]`; for VK that is index 2 = `computeShaderSPIRV`. The Vulkan sample reads `pDesc.computeShaderSPIRV` directly (`nrd_wrapper.cpp:520-521`).

**Dedup detail that matters for counting**: identical SPIR-V pointers collapse to one pipeline (`InstanceImpl.cpp:577-591`), so multiple denoisers sharing a pass (e.g. two `REFERENCE` instances) reuse one `VkPipeline`.

### 3.2 Descriptor set layouts — the exact bindings

The SPIR-V was compiled by DXC with ShaderMake's register shifts: `-fvk-s-shift 0 <space>`, `-fvk-t-shift 20 <space>`, `-fvk-b-shift 2 <space>`, `-fvk-u-shift 3 <space>` for spaces 0..7 (`ShaderMake/ShaderMake.cpp:1085-1094`, values from NRD's `CMakeLists.txt:88-91` and `CMakeLists.txt:334-337`). DXC maps a DX register to `binding = register + shift` and DX `space` to the SPIR-V `set`. NRD's shaders declare (`Shaders/NRD.hlsli:144-157`):

* cbuffer `b0, space1` → **set 1, binding 2**
* samplers `s0, s1, space1` → **set 1, bindings 0 and 1**
* SRVs `t<n>, space0` → **set 0, binding 20+n**
* UAVs `u<n>, space0` → **set 0, binding 3+n**

So, generically (offsets from `LibraryDesc::spirvBindingOffsets`, set indices from `InstanceDesc`):

**Set 0** — "resources" (`resourcesSpaceIndex` = 0), all `stageFlags = VK_SHADER_STAGE_COMPUTE_BIT`, `descriptorCount = 1` each:

| binding | VkDescriptorType | count | meaning |
|---|---|---|---|
| `storageTextureAndBufferOffset + u`, `u ∈ [0, descriptorPoolDesc.perSetStorageTexturesMaxNum)` | `VK_DESCRIPTOR_TYPE_STORAGE_IMAGE` | 1 | UAV outputs (and `IN_MV`, which REBLUR writes) |
| `textureOffset + t`, `t ∈ [0, descriptorPoolDesc.perSetTexturesMaxNum)` | `VK_DESCRIPTOR_TYPE_SAMPLED_IMAGE` | 1 | SRV inputs |

With the stock offsets these are bindings **3…(3+S−1)** and **20…(20+T−1)**. They never collide for a stock build (for `REBLUR_DIFFUSE_SPECULAR` / `RELAX_DIFFUSE_SPECULAR` in radiance mode: S = 7, T = 18 — hand-derived in §12; the authoritative values are `InstanceDesc::descriptorPoolDesc.perSetTexturesMaxNum` / `perSetStorageTexturesMaxNum`, which `nrdshim_get_stats` should expose).

**Set 1** — "CB + samplers" (`constantBufferAndSamplersSpaceIndex` = 1):

| binding | VkDescriptorType | count | meaning |
|---|---|---|---|
| `samplerOffset + samplersBaseRegisterIndex + i`, `i ∈ [0, samplersNum)` → 0 and 1 | `VK_DESCRIPTOR_TYPE_SAMPLER` | 1 | immutable samplers: `NEAREST_CLAMP` (i=0), `LINEAR_CLAMP` (i=1) |
| `constantBufferOffset + constantBufferRegisterIndex` → 2 | `VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER` (or `..._DYNAMIC`) | 1 | the constants block |

Sampler creation parameters (from the sample, `nrd_wrapper.cpp:233-247` and NRD's NRI mapping `NRDIntegration.hpp:387-398`): `magFilter/minFilter = NEAREST` for `Sampler::NEAREST_CLAMP` and `LINEAR` for `Sampler::LINEAR_CLAMP`, `addressModeU = addressModeV = VK_SAMPLER_ADDRESS_MODE_CLAMP_TO_EDGE`, `mipmapMode = VK_SAMPLER_MIPMAP_MODE_NEAREST`. NRD never samples with an explicit LOD, so MIP filters and anisotropy are irrelevant; a single-mip texture is a hard requirement (`NRDIntegration.h:134`: *"Texture requirements: 2D, 1 layer, 1 mip"*).

**Push constants: none.** `PipelineDesc` has no push-constant field, `InstanceDesc` has none, and both reference integrations create the pipeline layout with `pushConstantRangeCount = 0` (`nrd_wrapper.cpp:511-517`; NRI's `PipelineLayoutDesc` at `NRDIntegration.hpp:410-421` sets no push constants). The shaders contain no `[[vk::push_constant]]` block; a cbuffer always becomes a SPIR-V `Uniform` block, i.e. a UBO descriptor. Do not try to pass the constants through push constants — the SPIR-V was compiled for a UBO.

### 3.3 Pipeline layout

One **shared** `VkPipelineLayout` for all pipelines is what NRD's own integration does (`NRDIntegration.hpp:421` creates it once; `RecreatePipelines` at :221-228 reuses `m_PipelineLayout` for every pipeline):

```cpp
VkDescriptorSetLayout setLayouts[2] = { resourcesLayout /*set0*/, cbSamplerLayout /*set1*/ };
VkPipelineLayoutCreateInfo plci{};
plci.setLayoutCount = 2;
plci.pSetLayouts = setLayouts;
plci.pushConstantRangeCount = 0;
```

The sample instead creates a **per-pipeline set-0 layout** containing only the bindings that pipeline uses (`nrd_wrapper.cpp:466-502`), because it needs a matching layout for `vkCmdPushDescriptorSetKHR`. That is also legal (set 1 stays shared). Either works; a single shared set-0 layout with the maximum binding counts is simpler and is what the descriptor-pool sizing in `InstanceDesc::descriptorPoolDesc` assumes.

### 3.4 Creating the pipelines

```cpp
VkComputePipelineCreateInfo ci{ VK_STRUCTURE_TYPE_COMPUTE_PIPELINE_CREATE_INFO };
ci.stage.sType  = VK_STRUCTURE_TYPE_PIPELINE_SHADER_STAGE_CREATE_INFO;
ci.stage.stage  = VK_SHADER_STAGE_COMPUTE_BIT;
ci.stage.module = shaderModule;                    // from computeShaderSPIRV
ci.stage.pName  = instanceDesc.shaderEntryPoint;   // "main"
ci.layout       = sharedPipelineLayout;
vkCreateComputePipelines(device, VK_NULL_HANDLE /*cache*/, instanceDesc.pipelinesNum, cis, nullptr, pipelines);
```

The sample hardcodes `pName = "main"` (`nrd_wrapper.cpp:527`) and passes `VK_NULL_HANDLE` as the pipeline cache (`:533`). Keeping a `VkPipelineCache` is fine and recommended for first-run cost. Pipelines can be created in parallel (the sample uses `#pragma omp parallel for`, `:457`). Note the NRD build defines `-fPIC -fvisibility=hidden -Werror -Wextra` on GCC/Clang (`CMakeLists.txt:278-299`) — if you add your own compile options to NRD, expect `-Werror` breakage.

### 3.5 Descriptor pool sizing hints from NRD

`InstanceDesc::descriptorPoolDesc` (`InstanceImpl.cpp:652-698`) is computed as:

* `setsMaxNum` = Σ over *unique pass names* of `maxRepeatNum` + number of clear resources (for potential `CLEAR_AND_RESTART` frames).
* `perSetTexturesMaxNum` = max over unique passes of the number of `TEXTURE` resources in a single dispatch.
* `perSetStorageTexturesMaxNum` = same for `STORAGE_TEXTURE`.
* `totalTexturesNum` / `totalStorageTexturesNum` = Σ over unique passes of (`resources * maxRepeatNum`) — the *total* number of descriptors you will ever need simultaneously in one frame.

The sample ignores these entirely because it uses push descriptors (`nrd_wrapper.cpp`, no reference to `descriptorPoolDesc`). A portable shim that allocates real descriptor sets **must** use them (§11.4).

`maxRepeatNum` (`Source/InstanceImpl.h:198-209`, comment at :207: *"must be same for all permutations (i.e. for same 'name')"*) is >1 for pipelines that are dispatched N times per frame with different data — REBLUR hit-distance reconstruction (4), pre-pass (2), temporal accumulation (8), post-blur (2), and RELAX's A-trous (`maxRepeatNum = (RELAX_MAX_ATROUS_PASS_NUM - 2 + 1) / 2`, `Source/Denoisers/Relax_DiffuseSpecular.hpp:285`).

### 4.1 The descriptor structs

```cpp

struct TextureDesc { Format format; uint16_t downsampleFactor; };        // NRDDescs.h:416-420

```

`DispatchDesc::resources` is the **concatenation** of the ranges in `PipelineDesc::resourceRanges` (`NRDDescs.h:516`): first all `TEXTURE` entries, then all `STORAGE_TEXTURE` entries, in the order the denoiser pushed them. `ResourceDesc::type` tells you where the resource lives:

* `ResourceType::PERMANENT_POOL` → your `VkImage` for `InstanceDesc::permanentPool[indexInPool]`
* `ResourceType::TRANSIENT_POOL` → your `VkImage` for `InstanceDesc::transientPool[indexInPool]`
* anything else → the host texture you bound for that `ResourceType` slot

### 4.3 Pool allocation (the shim's job, not the host's)

For every entry of `InstanceDesc::permanentPool` and `transientPool` (`TextureDesc{format, downsampleFactor}`) the shim must create one 2D image with `mipLevels = 1`, `arrayLayers = 1`, `samples = 1`, dimensions `ceil(resourceSize / downsampleFactor)`, the mapped `VkFormat`, and `usage = VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_STORAGE_BIT` — exactly what `NRDIntegration.hpp:265-275` does (NRI `SHADER_RESOURCE | SHADER_RESOURCE_STORAGE`) and what the sample hardcodes (`nrd_wrapper.cpp:337-354`, and its VK wrapper path `NRDIntegration.hpp:688` comment: `VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_STORAGE_BIT`). No `TRANSFER_*` usage is required (the sample's `vkCmdClearColorImage` at init is the only transfer-less clear allowed since `vkCmdClearColorImage` needs `TRANSFER_DST`… note it does enable it via nvvk defaults; a shim can skip the clear and use `CLEAR_AND_RESTART`).

Sizes (derived by enumeration of `AddTextureTo{Permanent,Transient}Pool` for `REBLUR_DIFFUSE_SPECULAR`, `Reblur_DiffuseSpecular.hpp:37-69`): 13 permanent + 8 transient textures per REBLUR diffuse+specular instance; the sizes depend only on the denoiser, never on the resolution (the resolution is factored in by the integration). README's memory table (`README.md:937-997`) gives the expected VRAM: 1080p `REBLUR_DIFFUSE_SPECULAR` = 148.12 MB total, 88.88 MB persistent (must survive across frames), 59.25 MB aliasable.

### 4.5 Exactly what the host must provide, and what it must not

**REBLUR (standard mode, `Denoiser::REBLUR_DIFFUSE_SPECULAR`)** — 7 mandatory resources:

| # | Slot | Host texture (from the prompt) | Requirements |
|---|---|---|---|
| 1 | `IN_MV` | render-pixel-space motion vectors (rg16f) | non-jittered, `prev - cur`; **needs `VK_IMAGE_USAGE_STORAGE_BIT`** because REBLUR's temporal-stabilization pass writes it; content is modified in place by NRD |
| 2 | `IN_NORMAL_ROUGHNESS` | world normal + roughness (rgba16f) | must match `LibraryDesc::normalEncoding`; NRD asserts the format at the first `Denoise` (`NRDIntegration.hpp:523-550`) |
| 3 | `IN_VIEWZ` | linear view Z derived from reversed-Z depth (r32f) | R16f+ allowed; must not be INF; sky pixels must be `> denoisingRange` |
| 4 | `IN_DIFF_RADIANCE_HITDIST` | noisy diffuse radiance+hitdist (rgba16f) | **packed** (YCoCg for REBLUR) and *demodulated* (albedo divided out) |
| 5 | `IN_SPEC_RADIANCE_HITDIST` | noisy specular radiance+hitdist (rgba16f) | same |
| 6 | `OUT_DIFF_RADIANCE_HITDIST` | denoised diffuse output | R11G11B10f+; `VK_IMAGE_USAGE_STORAGE_BIT`; treated as write-only by REBLUR |
| 7 | `OUT_SPEC_RADIANCE_HITDIST` | denoised specular output | same |

Optional (only if the corresponding feature flag is enabled): `IN_DIFF_CONFIDENCE` + `IN_SPEC_CONFIDENCE` (R8+, `isHistoryConfidenceAvailable`), `IN_DISOCCLUSION_THRESHOLD_MIX` (R8+, `isDisocclusionThresholdMixAvailable`), `OUT_VALIDATION` (RGBA8+, `enableValidation`).

**Not consumed by NRD at all** (important, because the host already produces them):
* **diffuse albedo / specular albedo (Rf0)**: NRD never sees material properties. `README.md:431`: *"NRD doesn't use 'baseColor' and 'metalness' anywhere for denoising. All materials must be de-modulated before denoising on the application side"*. They are used in the host's own front-end to compute `NRD_MaterialFactors` (`Shaders/NRD.hlsli:727`) for demodulation, and again after denoising to re-modulate.
* **specular motion vectors**: NRD 4.17 has exactly one `IN_MV` slot for both lobes; it *derives* specular motion internally via `ReblurSettings::specularProbabilityThresholdsForMvModification` (`NRDSettings.h:311-312`). `NRDDescs.h:147` says directly: *"A generic solution requires reflection MVs, which NRD currently doesn't ask for."* Keep specular MVs host-side (useful for DLSS-RR, not for NRD).
* **penumbra / occlusion**: `IN_PENUMBRA` belongs to SIGMA only. REBLUR's occlusion output is the `.w` channel of its radiance outputs.

**RELAX** (`RELAX_DIFFUSE_SPECULAR`) needs the same 7 slots. Differences that matter: RELAX's pre-pass writes directly into `OUT_DIFF/OUT_SPEC_RADIANCE_HITDIST` (`Relax_DiffuseSpecular.hpp:116-117`) and later passes read those same textures as SRVs (`:140-141`, `:188-189`), and the A-trous passes write `OUT_*` on the last iteration (`:270-272`). So for RELAX the output textures are genuinely read+written and must be usable as both SRV and UAV in the same frame.

### 5.5 Checkerboard / upscaler interaction

* **Checkerboard off** (default) changes nothing about the required inputs.
* **Checkerboard on** requires `NRD_SUPPORTS_CHECKERBOARD=1` (build-time, default ON) and changes the *input layout*: all inputs are at logical **full** resolution, but the noisy signals are *"tightly packed to the LEFT HALF of the texture (the input pixel = 2x1 screen pixel)"*, guides stay 1×1 (`NRDSettings.h:38-44`). Upsampling is internal. Not recommended for the first integration.
* **Upscalers (DLSS/FSR/XESS/TAAU)** do not change NRD's required inputs. NRD's temporal filter naturally suppresses jitter (`README.md:641-652`); with SH denoisers the app applies an SG/SH resolve + re-jitter after denoising. Ordering: denoise at render resolution → resolve → upscale.
* **Frame generation**: use the *real* FPS for `GetMaxAccumulatedFrameNum` (`README.md:711-713`).

```

    nrd::CreateInstance(icd, instance)         -> instance                    (NRD.h:51)
    nrd::GetInstanceDesc(*instance)            -> pipelines/pools/samplers    (NRD.h:56)

    [shim] NewFrame equivalent: descriptor-pool index = frame % queuedFrameNum;
           vkResetDescriptorPool(pool[index]);                    (NRDIntegration.hpp:449-485)
    nrd::SetCommonSettings(*instance, commonSettings)             (NRD.h:59)

    nrd::GetComputeDispatches(*instance, ids, n, descs, num)      (NRD.h:66)

               vkCmdBindDescriptorSets(...)
               vkCmdDispatch(d.gridWidth, d.gridHeight, 1)
    [shim] optional final barrier to restore host layouts

on resize / denoiser change:
    nrd::DestroyInstance(*instance)                                (NRD.h:52)
```

`NewFrame`, `SetCommonSettings`, `SetDenoiserSettings`, `Denoise` are the NRI-layer names (`NRDIntegration.h:233-252`); the core API equivalents are the four `nrd::` calls above. Order matters: `SetCommonSettings` **must** precede `GetComputeDispatches` (the common settings feed the constant data, `InstanceImpl.cpp:251-454` then `:487-561`), and `SetDenoiserSettings` must precede it too (`:456-485`).

### 6.2 `DispatchDesc` fields the host consumes

```cpp
struct DispatchDesc {                       // NRDDescs.h:510-529
    const char* name;                       // debug label
    Identifier identifier;                  // which denoiser instance
    const ResourceDesc* resources; uint32_t resourcesNum;
    const uint8_t* constantBufferData; uint32_t constantBufferDataSize;
    bool constantBufferDataMatchesPreviousDispatch;
    uint16_t pipelineIndex; uint16_t gridWidth; uint16_t gridHeight;
};
```

* `resources`/`resourcesNum`: see §4.1. Memory is instance-owned and invalidated by the next `GetComputeDispatches` (`NRD.h:65`).
* `constantBufferDataSize == 0` only for clear dispatches; always bind a valid UBO anyway (§3.1).
* `constantBufferDataMatchesPreviousDispatch`: NRD sets this by `memcmp` against the *immediately preceding* dispatch **within the same call** (`InstanceImpl.cpp:546-554`). Use it to skip a redundant upload.
* `gridWidth`/`gridHeight`: already computed as `ceil(rectSize / (downsampleFactor * numThreads))` (`InstanceImpl.cpp:772-817`), where `downsampleFactor` comes from the pass (1, or 16 for the tile-classification passes, `Reblur_DiffuseSpecular.hpp:69`; sentinels `USE_PREV_DIMS = 0xFFFF` and `IGNORE_RS = 0xFFFE` select prev/viewport dims, `InstanceImpl.h:152-153`). **Never recompute the grid yourself**; always dispatch `{gridWidth, gridHeight, 1}`.
* `pipelineIndex`: index into `InstanceDesc::pipelines`.

### 6.3 How many dispatches per frame

Derived from `Update_Reblur` (`Source/Reblur.cpp:98-199`), `Update_ReblurOcclusion` (:201-281), `Update_Relax` (`Source/Relax.cpp:183-284`) and the pass tables:

| Configuration | Dispatches |
|---|---|
| `REBLUR_DIFFUSE_SPECULAR`, defaults (prepass on, stabilization on, checkerboard OFF, `splitScreen 0`, `enableValidation false`, hitdist-reconstruction OFF) | **7**: classify tiles, pre-pass, temporal accumulation, history fix, blur, post-blur, temporal stabilization |
| `REBLUR_DIFFUSE_SPECULAR` + `enableValidation` | 8 |
| `REBLUR_DIFFUSE_SPECULAR` + `hitDistanceReconstructionMode != OFF` | +1 |
| `REBLUR_DIFFUSE_SPECULAR` with `diffusePrepassBlurRadius = specularPrepassBlurRadius = 0` | −1 |
| `RELAX_DIFFUSE_SPECULAR`, defaults (`atrousIterationNum 5`, `enableAntiFirefly false`) | **10**: classify tiles, pre-pass, temporal accumulation, history fix, history clamping, 5× A-trous |
| `RELAX_DIFFUSE_SPECULAR` + `enableAntiFirefly` | +2 (copy, anti-firefly) |
| `RELAX_DIFFUSE_SPECULAR` + `enableValidation` | +1 |
| any of the above with `splitScreen >= 1` | exactly 1 (pass-through) |
| any frame with `accumulationMode == CLEAR_AND_RESTART` | **+ 1 clear dispatch per unique storage resource** (including ping-pong partners, excluding `OUT_VALIDATION`) — enumerated for `REBLUR_DIFFUSE_SPECULAR`: **24** (8 transient textures + 13 permanent + 3 host textures: `IN_MV`, `OUT_DIFF`, `OUT_SPEC`), injected *before* the regular dispatches (`InstanceImpl.cpp:172-219` builds the list, `:499-523` injects it). |

Consequences for the shim: (1) the dispatch count per frame is **variable** — never cache or index by position; (2) frame 0 always takes the `CLEAR_AND_RESTART` path because NRD forces it (`InstanceImpl.cpp:257-260`), so the first frame is the worst case for descriptor-pool and command-buffer sizing; (3) the clear pipelines are the storage-only, constants-less ones.

For the same reason, the descriptor pool must be sized for `descriptorPoolDesc.setsMaxNum` sets **per queued frame**: for a single `REBLUR_DIFFUSE_SPECULAR` instance that is Σ(maxRepeatNum over unique pass names) = 1+4+2+8+1+1+2+1+1+1 = 22, plus 24 clear sets ⇒ ≈46. Use the runtime-reported numbers, not these derived ones.

### 6.4 What the host binds per dispatch, and the barrier rule

The algorithm to replicate (this is `NRDIntegration.hpp:715-882`, which is the Vulkan-shaped reference even though it runs through NRI):

```
for each dispatch d:
    descriptorSet = allocate 1 set from pool[frame % queuedFrameNum]
    n = 0
    for each range r in pipelines[d.pipelineIndex].resourceRanges:
        for j in [0, r.descriptorsNum):
            rd = d.resources[n++]
            image = (rd.type == TRANSIENT_POOL) ? transientPool[rd.indexInPool]
                  : (rd.type == PERMANENT_POOL) ? permanentPool[rd.indexInPool]
                  : hostResource[rd.type]
            after = (rd.descriptorType == TEXTURE)
                      ? {access: SHADER_READ,    layout: SHADER_READ_ONLY_OPTIMAL}
                      : {access: SHADER_READ|SHADER_WRITE, layout: GENERAL}
            needBarrier = (after != image.state) ||
                          (rd.descriptorType == STORAGE_TEXTURE && image.state.layout == GENERAL)
            image.state = after
            write descriptor: SRV -> VkDescriptorImageInfo{imageView}, type SAMPLED_IMAGE
                              UAV -> VkDescriptorImageInfo{imageView}, type STORAGE_IMAGE
    vkUpdateDescriptorSets(...)          // the two ranges: SRV at base textureOffset, UAV at base storageOffset
    if d.constantBufferDataSize && !d.constantBufferDataMatchesPreviousDispatch:
        copy d.constantBufferData .. +size into the UBO at a fresh ring offset (aligned)
    vkCmdBindPipeline(cmd, pipelines[d.pipelineIndex])
    vkCmdBindDescriptorSets(cmd, COMPUTE, layout, /*firstSet*/0, 2, {set0, set1}, dynamicOffsets)
    vkCmdPipelineBarrier(cmd, ...)       // all accumulated image barriers, src=dst=COMPUTE_SHADER
    vkCmdDispatch(cmd, d.gridWidth, d.gridHeight, 1)
```

Key points, each traceable to code:

* **Two states only**: SRV ⇒ `VK_IMAGE_LAYOUT_SHADER_READ_ONLY_OPTIMAL` + `VK_ACCESS_SHADER_READ_BIT`; UAV ⇒ `VK_IMAGE_LAYOUT_GENERAL` + read|write accesses. Every barrier is `srcStageMask = dstStageMask = VK_PIPELINE_STAGE_COMPUTE_SHADER_BIT` (`NRDIntegration.hpp:761-778`).
* **UAV→UAV needs a barrier even with no layout change** — NRD's integration forces it (`isStorageBarrier`, `:768-776`). This is essential: NRD repeatedly reads and writes the same history textures in consecutive passes.
* **`baseRange` convention** (`:840`): with two ranges, range 0 = SRV, range 1 = UAV; with one range it is the UAV range. (Guaranteed by how NRD builds ranges; the shim should still switch on `resourceRanges[i].descriptorType` rather than assume.)
* **Shape vs identity** (see §10.6): a pipeline may serve several dispatches with different resources, so always take the descriptor *shape* from `pipelines[d.pipelineIndex].resourceRanges` and the descriptor *contents* from `d.resources[n]`, walking the ranges in order.
* Descriptors must be written **per dispatch**: NRD uses different binding counts per pass (e.g. 1 SRV + 1 UAV for the clear/classify passes vs 18 SRV + 7 UAV for temporal accumulation). Bindings not written by a dispatch are left invalid; that is legal because they are not statically used by that pipeline — but only if each dispatch gets its own set (or you use push descriptors / `PARTIALLY_BOUND`).
* `resourceSnapshot.restoreInitialState` (`NRDIntegration.hpp:581-611`) shows how to hand the resources back in the host's layouts at the end: for each texture whose state changed, emit one barrier back to the declared initial state.
* **Descriptor caching**: NRI caches `VkImageView`s keyed by `(native texture handle, isStorage)` (`:86-91`, `:781-807`) and destroys all cached views per frame when whole-lifetime caching is off. For a shim, the simplest correct scheme is: host-owned `VkImageView`s are created by the *host* (one SRV view + one storage view per NRD-bound texture) and passed in; the shim only writes descriptors. That removes the lifetime hazard entirely.

### 6.5 Submitting / synchronization

The shim never submits. Everything is recorded into the host's `VkCommandBuffer` inside the host's existing frame submission, so the host's timeline semaphore covers it. Two details:

* The UBO must be valid until the frame's submission completes. Either (a) inline the constants into the command stream with `vkCmdUpdateBuffer` (what the sample does: `nrd_wrapper.cpp:670`, wrapped in two real buffer barriers `:656-685`), or (b) keep `queuedFrameNum` host-visible UBO rings and index them by `frame % queuedFrameNum`. Option (a) needs `VK_IMAGE/BUFFER` transfer usage on the UBO and adds two barriers per dispatch; option (b) is what a fixed-function shim usually wants and needs no extra barriers if you use `vkCmdUpdateBuffer`-free writes plus a single "host write → shader read" barrier at frame start, or simply rely on the host's frame-level fencing.
* **Never keep `DispatchDesc::constantBufferData` pointers around**: they point into NRD's internal 128 KB scratch buffer (`InstanceImpl.h:150`, `InstanceImpl.cpp:488-489`, `:785-796`) which the next `GetComputeDispatches` overwrites. Copy immediately (into the mapped UBO or via `vkCmdUpdateBuffer`).
* Queue: any compute-capable queue. NRD itself has no queue-family requirement; the official sample uses a single graphics queue (`nrd_sample.cpp:1526`). If the guides were produced on a different queue family than the one recording NRD dispatches, the images must be `VK_SHARING_MODE_CONCURRENT` (or the shim must emit a queue-family-ownership transfer, which it cannot know how to do).

## 7. Shaders and build

### 7.1 SPIR-V generation and embedding

* Option name: **`NRD_EMBEDS_SPIRV_SHADERS`** (`CMakeLists.txt:21`): `option(NRD_EMBEDS_SPIRV_SHADERS "NRD embeds SPIRV shaders" ON)`; the two DX variants are `cmake_dependent_option(NRD_EMBEDS_DXIL_SHADERS ... ON "WIN32" OFF)` and `NRD_EMBEDS_DXBC_SHADERS` (:24-25). It is ON by default on **all** platforms — do not turn it off for a Vulkan build, or `computeShaderSPIRV.bytecode` will be null (the only guard is an `assert`, `InstanceImpl.cpp:572-574`).
* Mechanism: the `NRDShaders` custom target runs ShaderMake with `--headerBlob` (`CMakeLists.txt:338`, `:376-384`), producing `_Shaders/<Name>.cs.spirv.h` blob tables which are `#include`d by the C++ sources (e.g. `Source/Reblur.cpp:423-434`) and searched per permutation at runtime by `ShaderMake::FindPermutationInBlob` (`Source/InstanceImpl.h:53-57`). **All SPIR-V ships inside the library binary**; there is no runtime file I/O and no shader directory to deploy, and there is no public NRD API to fetch a blob by name (only `GetInstanceDesc()->pipelines[i].computeShaderSPIRV`). `3-PrepareSDK.sh` only copies the binary plus the *host*-side headers (`libNRD.so` at `:24`, `NRD.hlsli`/`NRDConfig.hlsli` at `:18-19`).
* ShaderMake arguments that matter (`CMakeLists.txt:330-347`): `--flatten --stripReflection --WX --sRegShift 0 --bRegShift 2 --uRegShift 3 --tRegShift 20 --headerBlob --allResourcesBound --vulkanVersion 1.2 --sourceDir Shaders -c Shaders/Shaders.cfg -D NRD_INTERNAL`, plus ShaderMake's own `-T cs -m 6_0`, `-spirv`, `-fspv-target-env=vulkan1.2`, `-fvk-use-entrypoint-name`, and the four `-fvk-*-shift` loops (`ShaderMake/ShaderMake.cpp:1077-1094`). `--allResourcesBound` maps to DXC's `-all_resources_bound` (:1058): the shaders assume every used resource is bound (hence "write a descriptor for every statically-used binding").
* So: **shader compilation happens at NRD build time**, requiring (1) the ShaderMake tool (auto-fetched, see §7.3) and (2) a DXC with SPIR-V support. NRD's CMake uses `SHADERMAKE_PATH` if provided; otherwise it assumes a `ShaderMake` executable and takes the compiler paths from `DXC_PATH` / `DXC_SPIRV_PATH` / `FXC_PATH` (`CMakeLists.txt:349-357`), passing `DXC_SPIRV_PATH` as `--compiler` for the SPIRV pass (:366). GitHub's Ubuntu CI installs only `ninja-build` and still builds SPIR-V, i.e. its image ships a usable `dxc`.

### 7.3 Consuming NRD via CMake FetchContent

NRD itself is *not* a `FetchContent`-documented package; the official Vulkan sample fetches it with `FetchContent` and sets options before `FetchContent_MakeAvailable`. The sample's exact block (read at HEAD `a9119d1`) is:

Note the actual repository URL is `https://github.com/NVIDIA-RTX/NRD.git` (not `fetchcontent_declare`, which is NRD's own internal spelling for its *dependencies* at `CMakeLists.txt:121`, `:132`, `:151`). For this project pin **`GIT_TAG v4.17.3`** (commit `792eff196afdd350fd9c3f862119017ccb438a0e`; SHA pinning also works).

Required/important options for a Vulkan-only shim:

```cmake
set(NRD_STATIC_LIBRARY ON)            # one static lib, no NRD_API dllexport; links into libnrdshim.so
set(NRD_NRI OFF)                      # default; do not pull NRI
set(NRD_EMBEDS_SPIRV_SHADERS ON)      # default; MUST stay ON
set(NRD_EMBEDS_DXIL_SHADERS OFF)      # default OFF on non-Windows
set(NRD_EMBEDS_DXBC_SHADERS OFF)      # default OFF on non-Windows
set(NRD_NORMAL_ENCODING 2)            # default: R10_G10_B10_A2_UNORM
set(NRD_ROUGHNESS_ENCODING 1)         # default: LINEAR
set(NRD_SUPPORTS_CHECKERBOARD 1)      # default ON — keep consistent with runtime settings
set(NRD_SUPPORTS_HISTORY_CONFIDENCE 1)
set(NRD_SUPPORTS_DISOCCLUSION_THRESHOLD_MIX 1)
set(NRD_SUPPORTS_ANTIFIREFLY 1)
set(NRD_SUPPORTS_VIEWPORT_OFFSET 0)   # keep 0 unless rectOrigin is used

# set(NRD_SHADERS_PATH "${CMAKE_BINARY_DIR}/nrd_shaders")   # optional; default is <nrd-src>/_Shaders
```

**Important warning about these compile-time switches**: `LibraryDesc` exposes *only* the version and the two encodings — **not** the `NRD_SUPPORTS_*` flags. If the runtime asks for a feature the library was built without, the call fails at runtime (`SetCommonSettings` → `INVALID_ARGUMENT` for `rectOrigin`/confidence/mix, asserts at `InstanceImpl.cpp:321-328`; `SetDenoiserSettings` → `INVALID_ARGUMENT` for checkerboard/anti-firefly, `:474-480`). Pin the options in the shim's CMake and treat them as part of the ABI.

Offline/hermetic builds: NRD's dependency fetches use `fetchcontent_declare(<name> URL ...)` with the lowercase names `shadermake` and `mathlib` (`CMakeLists.txt:121-139`), so CMake's standard override variables `FETCHCONTENT_SOURCE_DIR_SHADERMAKE` and `FETCHCONTENT_SOURCE_DIR_MATHLIB` can point at pre-downloaded sources; likewise `-DFETCHCONTENT_FULLY_DISCONNECTED=ON` after a first configure. `SHADERMAKE_PATH`/`DXC_SPIRV_PATH` let you use pre-installed tools instead of the fetched ones.

### 7.4 Shipped artifacts

With `NRD_STATIC_LIBRARY=ON` the shim produces exactly one redistributable: `libnrdshim.so` (or `ngxshim`-style `.dll`), containing NRD + its embedded SPIR-V. With `NRD_STATIC_LIBRARY=OFF` you ship `libNRD.so` + `libnrdshim.so`. Either satisfies the license's "object code format" distribution clause (§9). Recommended: static, mirroring `native/ngx_shim/CMakeLists.txt:33-50` (which links the NGX static lib directly into `libngxshim.so`).

### 7.5 Host-side shader obligations (Slang, not HLSL)

The host's shaders are **Slang** (`shaders/pipelines/**/*.slang`, compiled by `slangc` to SPIR-V). `Shaders/NRD.hlsli` is DXC-HLSL: it branches on `__hlsl_dx_compiler`/`__spirv__` (`NRD.hlsli:135-164`, `:273-307`), uses `#pragma pack_matrix(column_major)` (:315) and HLSL `cbuffer`/`register` syntax, so it cannot simply be `import`ed by Slang. The host therefore has two options:

1. **Port the ~10 helpers the host needs into Slang** (recommended; they are short and self-contained). The complete list with citations:
   * `NRD_FrontEnd_PackNormalAndRoughness(float3 N, float roughness, float materialID)` — `NRD.hlsli:690`; decode side `NRD_FrontEnd_UnpackNormalAndRoughness` — `:650`/`:681` (oct-packed 10:10:10:2 for the default encoding).
   * `REBLUR_FrontEnd_GetNormHitDist(hitDist, viewZ, hitDistParams, roughness)` — `:774` (must match `ReblurSettings::hitDistanceParameters`).
   * `REBLUR_FrontEnd_PackRadianceAndNormHitDist(radiance, normHitDist, sanitize)` — `:787` (does `_NRD_LinearToYCoCg`).
   * `REBLUR_BackEnd_UnpackRadianceAndNormHitDist` — `:842` (inverse YCoCg; `.w` = AO/SO).
   * `NRD_MaterialFactors(N, V, albedo, Rf0, roughness, out diffFactor, out specFactor)` — `:727` (for demodulation/re-modulation).
   * For RELAX: `RELAX_FrontEnd_PackRadianceAndHitDist` — `:884`, `RELAX_BackEnd_UnpackRadiance` — `:919`.
2. Compile a small DXC/HLSL compute pass that includes `NRD.hlsli` + the generated `NRDConfig.hlsli` and writes the packed guides into a second set of textures. This keeps bit-exact compatibility at the cost of an extra full-screen pass and a second shader toolchain.

Either way, **both `NRD.hlsli` and the generated `NRDConfig.hlsli` must come from the same NRD revision and the same CMake options as the library build** (the encoding macros change the bit layout: `NRDConfig.hlsli` is generated at `CMakeLists.txt:75-85` and consumed at `NRD.hlsli:78`).

### 8.1 `nvpro-samples/vk_denoise_nrd` (raw Vulkan, the closest analogue)

Repo `nvpro-samples/vk_denoise_nrd`, default branch `main`, HEAD `a9119d11d23b83adfc433afbddee5e01770a58d9` (2026-07-22), Apache-2.0. It pins NRD **v4.17.2** via FetchContent (commit `88b0457f…`). There is **no** `RealtimeDenoiser/src/main.cpp`; the app is `RealtimeDenoiser/src/nrd_sample.cpp` and the integration is `RealtimeDenoiser/src/nrd_wrapper.{hpp,cpp}` (121 + 702 lines).

**Public shape** (`nrd_wrapper.hpp`): `class NRDWrapper` (:34) constructed with `(nvvk::ResourceAllocator&, const nvvk::QueueInfo&, nvvk::SamplerPool&, uint16_t width, uint16_t height, const nvvk::Image userTexturePool[nrd::ResourceType::MAX_NUM])` (:56-62); `setUserPoolTexture(nrd::ResourceType, nvvk::Image)` (:64); `setCommonSettings(nrd::CommonSettings&)` (:67); `setREBLURSettings(const nrd::ReblurSettings&)` (:70); `setRELAXSettings(const nrd::RelaxSettings&)` (:71); `denoise(const nrd::Identifier*, uint32_t, VkCommandBuffer&)` (:77); `static VkFormat getNormalRoughnessFormat()` (:82). Private: `struct NRDPipeline { VkPipeline pipeline; VkPipelineLayout pipelineLayout; VkDescriptorSetLayout resourceDescriptorLayout; uint32_t numBindings; }` (:85-91).

**Instance + pipelines**: 4 denoiser entries (two REBLUR/RELAX + two `REFERENCE` ids) built as `nrd::InstanceCreationDesc{{} /*zeroed allocator callbacks*/, denoisers.data(), n}`, then `nrd::CreateInstance(...)` (`nrd_wrapper.cpp:154-164`). It never fills `nrd::InstanceDesc` — it *consumes* `nrd::GetInstanceDesc` (`:167`, `:365`, `:561`) and ignores `descriptorPoolDesc`, `constantBufferRegisterIndex`, `samplersBaseRegisterIndex` and `shaderEntryPoint` entirely. Pipeline layouts/set layouts are created as described in §3.2-3.3: set 0 with `VK_DESCRIPTOR_SET_LAYOUT_CREATE_PUSH_DESCRIPTOR_BIT_KHR` and only that pipeline's bindings (`:466-502`), set 1 with immutable samplers + one `UNIFORM_BUFFER` at binding 2 (`:380-422`), `assert(iDesc->constantBufferAndSamplersSpaceIndex == 1 && iDesc->resourcesSpaceIndex == 0)` with the comment *"NRD using these two set indexes is a hardcoded assumption that NRD promised not to break"* (`:507-508`). Pipelines: `nvvk::createShaderModule` from `computeShaderSPIRV`, `stage.pName = "main"`, `vkCreateComputePipelines(device, VK_NULL_HANDLE, ...)` (`:520-533`), compiled in an OpenMP parallel loop.

**Per-frame recording** (`nrd_wrapper.cpp:539-701`): `GetComputeDispatches` → for each dispatch: resolve `ResourceDesc` to images (`TRANSIENT_POOL` → `m_transientTextures[indexInPool]`, `PERMANENT_POOL` → `m_permanentTextures[indexInPool]`, else the user pool array indexed by the raw `ResourceType` value, `:618-630`) → (intended) per-resource barriers → `vkCmdUpdateBuffer` for constants when `hasConstantData && !constantBufferDataMatchesPreviousDispatch` with real `VkBufferMemoryBarrier`s around it (`:651-687`) → `vkCmdBindPipeline` → `vkCmdBindDescriptorSets(set=1)` for samplers+UBO → `vkCmdPushDescriptorSetKHR(set=0)` for the resources → `vkCmdDispatch(gridWidth, gridHeight, 1)`.

**Storage/layout model**: all wrapper-owned images are created with `VK_IMAGE_USAGE_SAMPLED_BIT | VK_IMAGE_USAGE_STORAGE_BIT` (`:337-354`) and put into `VK_IMAGE_LAYOUT_GENERAL` once at init (`:202-231`); user textures must already be in `GENERAL` and stay there. There is no state tracking. Device extensions required by the sample include `VK_KHR_push_descriptor` (mandatory, not optional) along with the ray-tracing set (`nrd_sample.cpp:1495-1504`); it runs on one graphics queue (`:1526`).

**Two caveats to not copy**:
1. **The per-dispatch image barriers are dead code at HEAD.** `nrd_wrapper.cpp:574` declares `std::vector<VkImageMemoryBarrier> imageBarriers;` but the lambdas at `:576-595` return a `VkImageMemoryBarrier2` whose result is discarded (`:638`), so `vkCmdPipelineBarrier` at `:645` gets `barrierCount = 0`. In the previous non-nvpro_core2 revision (commit `407092f2aea6`) the same code did push the barriers. Correct ordering today comes only from "everything stays in `GENERAL`" plus the app's coarse barriers around the whole NRD block. A new shim targeting mobile must implement the §6.4 rule explicitly.
2. Push descriptors are the reason the sample needs no descriptor pools; `VK_KHR_push_descriptor` is a desktop-oriented extension. Do not depend on it (§10.7).

### 8.2 NRD's own `Integration/NRDIntegration.hpp` (NRI)

The authoritative "map NRD onto a Vulkan-like RHI" document (`README.md:797`: *"can be used as a guide demonstrating how to map NRD API to a Vulkan-like RHI"*). Concrete things to lift:

* Blob selection across backends: `(&nrdPipelineDesc.computeShaderDXBC)[std::max((int32_t)deviceDesc.graphicsAPI - 1, 0)]` → index 2 for VK (`:213`).
* Pool texture creation incl. `downsampleFactor` and the FP16 promote/demote options (`:233-310`).
* Constant-buffer allocation: `viewSize = Align(constantBufferMaxDataSize, memoryAlignment.constantBufferOffset)`, `total = viewSize * setsMaxNum * queuedFrameNum` (`:313-314`), a ring cursor that wraps and a `constantBufferOffsetPrev` to honour `constantBufferDataMatchesPreviousDispatch` (`:815-837`).
* Pipeline layout derived from `spirvBindingOffsets` with `IGNORE_GLOBAL_SPIRV_OFFSETS` (`:359-422`) — NRI would otherwise apply its own binding shifts; on raw Vulkan this is simply "use the offsets as-is".
* Descriptor-pool sizing from `descriptorPoolDesc` (`:424-439`).
* Per-dispatch barriers incl. the UAV→UAV rule and the `baseRange` convention (`:760-778`, `:840`).
* `restoreInitialState` implementation (`:581-611`) — the pattern to hand resources back in the host's layouts.

The one thing it needs that a raw-Vulkan shim does not: an NRI device wrapper (`nriCreateDeviceFromVKDevice`, `:186`) and `nri::WrapperVKInterface`; the resource descriptors are just `{VKNonDispatchableHandle image; VKEnum format;}` (`NRDIntegration.h:78-82`) with usage forced to SAMPLED|STORAGE (`NRDIntegration.hpp:688`).

## 10. Risks and gotchas (ordered by likelihood of breaking a first integration)

1. **`IN_MV` is a read/write resource.** REBLUR's temporal-stabilization pass writes `IN_MV` (`Reblur_DiffuseSpecular.hpp:270`) — NRD patches motion vectors internally. The host's motion texture must be created with `VK_IMAGE_USAGE_STORAGE_BIT` and a storage-capable view, and the host must not assume the image still holds its original motion vectors after denoising (do not reuse it as an input to a later pass that expects raw MVs; re-generate it next frame or cache a copy).
2. **Every NRD-bound texture needs both `VK_IMAGE_USAGE_SAMPLED_BIT` and `VK_IMAGE_USAGE_STORAGE_BIT`.** The same resource appears as SRV in one pass and UAV in another (REBLUR: guides/history; RELAX: even `OUT_*` is read then written). NRD's own wrappers force `SAMPLED|STORAGE` on everything (`NRDIntegration.hpp:688`, sample `:337-354`). Creating a texture as sampled-only is the classic first crash/validation error.
3. **Storage-image format support.** NRD's internal pool uses `R8_UNORM`, `R16_UNORM`, `R16_UINT`, `R32_UINT`, `RG8_UNORM`, `R16_SFLOAT`, `RGBA16_SFLOAT`, `R32_SFLOAT`, `R11G11B10_UFLOAT`, `RGBA8_UNORM` and `R10_G10_B10_A2_UNORM` as **storage** images (see the per-denoiser pool tables). Each must report `VK_FORMAT_FEATURE_STORAGE_IMAGE_BIT` for `VK_IMAGE_TILING_OPTIMAL`. On desktop this is universal; on mobile it must be queried (`vkGetPhysicalDeviceFormatProperties`) at init, and the shim should refuse/fail gracefully with a clear error rather than producing validation errors at draw time.
4. **Unknown-format storage writes.** Every NRD output is declared with `[[vk::image_format("unknown")]]` (`Shaders/NRD.hlsli:137-142`, applied in `NRD_OUTPUT` at `:153`), so the SPIR-V declares format-less storage images. Writing one requires the device feature `shaderStorageImageWriteWithoutFormat` (core-ish on desktop, but a *feature bit* that must be enabled in `VkDeviceCreateInfo`). The SDK docs and the sample never mention it — **verify this with a validation-layer run** and enable the feature if reported. (Not determinable from the sources whether the driver tolerates it without the feature.)
5. **Layout transitions are mandatory and the sample's are broken.** See §8.1 caveat 1. Implement the §6.4 rule: SRV ⇒ `SHADER_READ_ONLY_OPTIMAL`, UAV ⇒ `GENERAL`, a barrier on every state change, **and on every UAV→UAV reuse even without a layout change**. Between the host's guide-writing pass and NRD you need a real barrier too (the host produces guides, NRD consumes them).
6. **Descriptor validity.** Each dispatch uses a different subset of the set-0 bindings (1…18 SRVs, 1…7 UAVs). Unwritten bindings are only legal because they are not statically used by that pipeline. Practical rule: allocate one descriptor set per dispatch and write exactly the bindings the ranges name; do **not** reuse one set across dispatches via `vkUpdateDescriptorSets` (updating a set referenced by an already-recorded command buffer is invalid).
   * **Pipelines are shared across permutations, so bindings must come from the dispatch.** Because pipelines dedup by SPIR-V pointer (`InstanceImpl.cpp:576-592`), the same `VkPipeline` serves several dispatches whose *contents* differ (RELAX A-trous ping/pong/final, REBLUR temporal accumulation with/without confidence inputs, dummy `IN_VIEWZ` substituted for absent optional signals: `Reblur.cpp:62`, `Relax.cpp:34`). The pipeline's `resourceRanges` gives you the *shape* (how many SRVs, how many UAVs, in what order); `DispatchDesc::resources[n]` gives you the *identity* of each slot. A shim that caches "binding k of this pipeline = texture X" from the first dispatch it sees will bind wrong textures on later dispatches — a silent, image-corrupting bug rather than a validation error.
7. **Do not require `VK_KHR_push_descriptor`.** The sample requires it (`nrd_sample.cpp:1495-1504`) and it is the reason it can ignore descriptor pools, but its presence is not guaranteed on mobile/Android drivers. The portable alternative (per-dispatch sets from per-frame pools sized by `descriptorPoolDesc`) is what NRD's own NRI integration does.
8. **Frames-in-flight vs descriptor pools.** Allocate `queuedFrameNum` (3 is the NRD default, `NRDIntegration.h:186`) descriptor pools and reset pool `frame % queuedFrameNum` at frame start; that is only safe if the host never has more than `queuedFrameNum` frames recording/in flight. The shim must take `queuedFrameNum` from the host (the host uses timeline semaphores, so it knows its own frame count).
9. **Constants are not push constants.** They go to a UBO at set 1 / binding `constantBufferOffset + constantBufferRegisterIndex` (=2). The UBO must be ≥ `InstanceDesc::constantBufferMaxDataSize` (≈0.9 KB for REBLUR radiance mode) and every per-dispatch slice must be aligned to `VkPhysicalDeviceLimits::minUniformBufferOffsetAlignment` when using `VK_DESCRIPTOR_TYPE_UNIFORM_BUFFER_DYNAMIC`. There is no push-constant path at all.
10. **`constantBufferData` lifetime.** `DispatchDesc::constantBufferData` points into NRD's internal scratch buffer (`InstanceImpl.h:150`, `InstanceImpl.cpp:785-796`) which is reset at the start of every `GetComputeDispatches` (`:488-489`). Copy the bytes immediately. If you plan to call `GetComputeDispatches` twice for two denoiser groups and then record, you will corrupt the first group's constants.
11. **`frameIndex` discipline.** +1 per frame; a restart is only allowed on a frame with `accumulationMode != CONTINUE`; the parity must match checkerboard mode if enabled (`NRDSettings.h:173-177`, `NRDIntegration.hpp:497-501`).
12. **`CommonSettings` must be fully initialized.** NRD `memcpy`s the whole struct (`InstanceImpl.cpp:254`), and from Java you must zero-fill before setting fields, otherwise garbage floats (e.g. `viewZScale = 0`, `denoisingRange = 0`) trip the asserts. `SetDenoiserSettings` similarly `memcpy`s `sizeof(settings)` (`:459`).
13. **Header/library version lockstep.** `SetDenoiserSettings` copies a struct whose size is fixed at library build time. Ship the exact NRD tag the shim was compiled against; check `LibraryDesc::{versionMajor,versionMinor,versionBuild}` at create time.
14. **First-frame dispatch count explosion.** `CLEAR_AND_RESTART` is forced on the first `SetCommonSettings` (`InstanceImpl.cpp:257-260`) and injects one clear dispatch per unique storage resource (~24 for a single `REBLUR_DIFFUSE_SPECULAR`). Pre-size pools/command buffers for `descriptorPoolDesc.setsMaxNum`, not for the steady-state count.
15. **Dispatch count and order are data-dependent.** `enableValidation`, `splitScreen`, `isHistoryConfidenceAvailable`, `isDisocclusionThresholdMixAvailable`, `hitDistanceReconstructionMode`, `atrousIterationNum`, `maxStabilizedFrameNum`, and `accumulationMode` all change which dispatches appear. Never index pipelines by position across frames; always re-read `GetComputeDispatches`.
16. **`GetComputeDispatches` failure modes.** `identifiersNum == 0` returns `SUCCESS` with 0 dispatches; a valid request whose denoisers produce nothing returns `INVALID_ARGUMENT` with `dispatchDescsNum == 0` (`InstanceImpl.cpp:492-497`, `:560`). Handle both.
17. **CommonSettings matrix conventions.** Column-major, non-jittered, `clipDepth = z/w`, LH or RH (auto-detected and converted, `InstanceImpl.cpp:374-389`), INF far plane allowed. Passing the jittered projection or a transposed matrix is the single most common cause of "denoiser smears everything". The host renders with **reversed-Z** hardware depth; NRD never sees the depth buffer — it sees `IN_VIEWZ` — but the `viewToClipMatrix` you pass must be the matrix actually used to render, and view-Z must be linearized by the host (whether MathLib's projection decomposition handles a reversed-Z matrix is **not determinable from the sources**; the safe recipe is to pass the standard (non-reversed) projection matrix and compute view-Z yourself).
18. **`resourceSize`/`rectSize` are `uint16_t`** — hard ceiling 65535 per axis, and both `resourceSize` and `resourceSizePrev` must be non-zero (`InstanceImpl.cpp:282-292`).
19. **Outside-`denoisingRange` pixels are not written** (`NRDDescs.h:107`, `README.md:803`). Sky/unlit pixels must have `viewZ > denoisingRange`, and the host must not expect the output textures to be fully defined for those pixels (composite them from the input, or treat `.w = 0` as "keep noisy").
20. **Packing and demodulation errors.** NRD expects in-lobe hit distance, normalized for REBLUR (`REBLUR_FrontEnd_GetNormHitDist`), `hitT = 0` for a skipped lobe with a clamped probability, and radiance that has had the BRDF divided out (`README.md:378-383`, `:495-516`, `:566-577`). Feeding irradiance, unnormalized hit distance, or raw `L/PDF` will look "denoised but wrong" (color shifts, darkening, temporal instability) rather than fail loudly.
21. **HDR range.** `README.md:809`: keep HDR radiance in `[0; 250]`; RELAX tracks second moments (`x²` must fit FP16), and pre-exposured colors are explicitly discouraged.
22. **Thread safety.** Not thread-safe; `GetComputeDispatches`' memory is instance-owned. One instance per thread/queue-recording context.
23. **Queue family.** No requirement, but the shim cannot do queue-family ownership transfers. Record NRD on the same queue family that produced the guides, or use `VK_SHARING_MODE_CONCURRENT` images.
24. **Resize = recreate.** Including all pool textures and pipelines. `IntegrationCreationDesc::resourceWidth/Height` show how the NRI layer forces static allocation and supports DRS only via `rectSize` (`NRDIntegration.hpp:489-492`).
25. **NRD's `-Werror` build.** If the shim's CMake adds compile options to the NRD target (or defines a new warning), the NRD build can fail on unrelated warnings (`CMakeLists.txt:287-290`). Don't touch the NRD target's flags.
26. **Format-mapping traps.** `Format::R10_G10_B10_A2_UNORM` → `VK_FORMAT_A2B10G10R10_UNORM_PACK32` (not `R10G10B10A2…`), `R11_G11_B10_UFLOAT` → `VK_FORMAT_B10G11R11_UFLOAT_PACK32`, `RGBA8_UINT` → `VK_FORMAT_A8B8G8R8_UINT_PACK32` and `R10_G10_B10_A2_UINT` → `VK_FORMAT_A2R10G10B10_UINT_PACK32` (the sample's table deliberately swizzles: `nrd_wrapper.cpp:50-105`, 43 entries with a `static_assert` against `nrd::Format::MAX_NUM`). Copy that table verbatim rather than re-deriving it.
27. **The shim is not an NRI host.** `NRDIntegration.hpp` cannot be used without pulling NRI v179 (`CMakeLists.txt:141-158`, `NRDIntegration.hpp:19-20`, `:115-124`) plus a wrapped device. Raw Vulkan is fully supported and is what the official Vulkan sample does.
28. **`RELAX` reads its own outputs.** Its pre-pass writes `OUT_*` and later passes read them (`Relax_DiffuseSpecular.hpp:116-117`, `:140-141`, `:188-189`), and the A-trous chain alternates ping/pong. Combined with gotcha 5 this means RELAX exercises the UAV→SRV→UAV barrier path more than REBLUR does; test it second, not first.

Notes on the FFM mapping: `VkCommandBuffer`/`VkDevice`/`VkImageView`/`VkImage` are passed as `uint64_t` (on 64-bit, `VK_DEFINE_NON_DISPATCHABLE_HANDLE` is `uint64_t`) or as `MemorySegment`/`void*` for dispatchable handles — either is fine via `Linker.downcallHandle(..., ValueLayout.JAVA_LONG)` / `ADDRESS`. All structs are plain-old-data with fixed layouts; mirror them with `MemoryLayout.structLayout(...)` in Java and keep a `static_assert(sizeof(...))` in the C header to catch layout drift. Identifiers are `uint32_t` and must match what the shim registered at create time (use the `Denoiser` enum value as the identifier when there is exactly one instance per denoiser — that is what the sample does, `nrd_wrapper.cpp:154-160`).

### 11.3 Vulkan objects the shim owns

| Object | Created from | Count |
|---|---|---|
| Pool `VkImage`s + `VkImageView`s (sampled and storage views) | `InstanceDesc::{permanentPoolSize, transientPoolSize}` + `TextureDesc{format, downsampleFactor}` | 13 permanent + 8 transient (REBLUR_DIFFUSE_SPECULAR) |
| `VkDescriptorSetLayout` set 0 | §3.2 (`perSetTexturesMaxNum` + `perSetStorageTexturesMaxNum` bindings) | 1 |
| `VkDescriptorSetLayout` set 1 | 2 immutable samplers + 1 UBO | 1 |
| `VkPipelineLayout` | 2 set layouts, 0 push-constant ranges | 1 |
| `VkPipeline` | one per `InstanceDesc::pipelines[i]` (`computeShaderSPIRV`, entry `shaderEntryPoint`) | `pipelinesNum` (29 for REBLUR + RELAX + REFERENCE, incl. 2 clear pipelines) |
| `VkDescriptorPool` | `setsMaxNum` sets, plus sampled/storage/UBO descriptor counts | `queuedFrameNum` |
| `VkBuffer` (UBO) | `Align(constantBufferMaxDataSize, minUniformBufferOffsetAlignment) * setsMaxNum * queuedFrameNum` | 1 (or `queuedFrameNum` if you prefer per-frame buffers) |
| Samplers | `InstanceDesc::samplers[]` → 2 `VkSampler`s (immutable in layout 1) | 2 |

All memory should go through the host's VMA allocator (pass VMA-allocated `VkImage`s in via the bindings; the shim can own a `VkDeviceMemory`-free design by letting the host allocate everything, which is even simpler: the shim only needs `VkImage`/`VkImageView` handles and never allocates).

### 11.4 Allocation strategy per dispatch

1. At frame start (`nrdshim_new_frame`): `vkResetDescriptorPool(pools[frame % queuedFrameNum])`, reset the UBO ring cursor, clear per-resource state to the declared `initialLayout`.
2. For each dispatch: allocate one set from the current pool; write only the bindings named by `pipelines[d.pipelineIndex].resourceRanges`; for each binding compute the target state (SRV/UAV per §6.4) and record a barrier when the state changes or when both before/after are UAV.
3. Constants: `memcpy` into the UBO slice immediately, remember its dynamic offset (if the previous dispatch had `constantBufferDataMatchesPreviousDispatch == true`, reuse the previous offset without copying).
4. Bind: `vkCmdBindPipeline`, `vkCmdBindDescriptorSets(firstSet=0, setCount=2, {set0,set1}, dynamicOffsets={0, cbOffset})`, `vkCmdPipelineBarrier(COMPUTE→COMPUTE)`, `vkCmdDispatch(gridWidth, gridHeight, 1)`.
5. At the end of `nrdshim_denoise`, for every bound resource whose state differs from `finalLayout`, emit one restore barrier (`NRDIntegration.hpp:581-611` pattern).

### 11.5 First-run verification checklist

1. `nrdshim_get_library_info` returns 4.17.3 and the expected encodings/offsets.
2. Create an instance with a single `REFERENCE` denoiser bound to the host's HDR color as both `IN_SIGNAL` and `OUT_SIGNAL`; verify a clean temporal accumulation (this validates barriers + descriptors + constants with zero packing risk).
3. Add `REBLUR_DIFFUSE` (not `_SPECULAR`): 3 guides + 1 packed input + 1 output. Use the host's shader to pack `REBLUR_FrontEnd_PackRadianceAndNormHitDist` (port to Slang).
4. Set `CommonSettings::splitScreen = 1.0f` for one frame — the output must equal the noisy input bit-for-bit-ish (pass-through dispatch) — this validates the resource wiring end to end.
5. Enable `enableValidation = true` and bind `OUT_VALIDATION`; read the 4×4 debug grid (`README.md:537-564`) to check normals/roughness/viewZ/MV correctness without guessing.
6. Only then move to `REBLUR_DIFFUSE_SPECULAR`, and later `RELAX_DIFFUSE_SPECULAR`.
7. Run with the Vulkan validation layer and `VK_LAYER_KHRONOS_validation` sync validation; the expected first complaints are storage-image-format and layout/barrier related (gotchas 2-5).

## 12. Explicitly undetermined from the sources

* **Whether `shaderStorageImageWriteWithoutFormat` must be enabled.** Inference from `[[vk::image_format("unknown")]]` (`NRD.hlsli:137-142`, `:153`); neither the SDK docs, `README.md`, nor the Vulkan sample mention the feature. Verify empirically with validation layers.
* **Exact `perSetTexturesMaxNum` / `perSetStorageTexturesMaxNum` / `setsMaxNum` values.** Hand-derived from the pass tables (18 / 7 / ≈46 for one `REBLUR_DIFFUSE_SPECULAR`); the authoritative source is `InstanceDesc::descriptorPoolDesc` at runtime, which `nrdshim_get_stats` exposes.
* **Exact dispatch counts and clear-dispatch counts.** Derived by enumerating `PushDispatch`/`PushOutput` sites; NRD does not print or expose counters. The clear count depends on the denoiser set.
* **Minimum Vulkan API version.** ShaderMake targets `vulkan1.2` (`CMakeLists.txt:340`, `ShaderMake.cpp:1077`). The sample never sets `VkApplicationInfo::apiVersion` and inherits nvpro_core2's default (1.4). No document states a floor. Practically: Vulkan 1.1+ features used are core in 1.0; the unknowns are the storage-image features of gotchas 3-4.
* **Whether a reversed-Z projection matrix is accepted by MathLib's projection decomposition.** `InstanceImpl.cpp:374-389` calls `DecomposeProjection(STYLE_D3D, STYLE_D3D, ...)` and only inspects `PROJ_LEFT_HANDED`/`PROJ_ORTHO`; the behaviour on a reversed-Z matrix is not documented.
* **Thread-safety guarantees of `nrd::Instance`.** No positive statement exists; `Integration/NRDIntegration.h:210` says `// Threadsafe: no` for the integration layer and the core API is stateful — treat as not thread-safe.
* **Whether NRD requires any specific queue family.** No: NRD makes no GAPI calls (`README.md:137`).
* **Third-party licenses bundled in NRD.** `LICENSE.txt:123-127` defers to "proprietary notices accompanying the SDK"; the tree contains no separate third-party notice file (MathLib and ShaderMake are fetched dependencies, not vendored).
