# DLSS-RR guide-buffer write-out audit

Repo: `/home/mizuki/Documents/CausticaForMobile` (Java + Slang Vulkan RT path tracer).
Scope: exactly what the path tracer stores into `gNormal`, `gAlbedo`, `gDepth`, `gMotion`,
`gSpecAlbedo`, `gSpecMotion`, plus the follow-up questions (hit distance, roughness/material-ID
availability, jitter, ID buffers). No repository files were modified; this file is the only output.

Everything below was read from source; every claim carries a `file:line` reference.

---

## 0. Executive summary

* All six guide images are written **exclusively by the primary pass**, in **one function**:
  `writeGuides()` at `shaders/pipelines/world/guides.slang:236-284`, called once from
  `primary.rgen.slang:251`. The indirect/continuation pass never touches them (it does not even
  import the guides module: `indirect.rgen.slang:21-33`).
* The actual store instructions are six consecutive lines, `guides.slang:278-283`.
* `gNormal.a` = **linear GGX alpha roughness**; `gAlbedo` = **diffuse albedo in linear ACEScg**;
  `gDepth` = **hardware reversed-Z `z/w`**, *not* linear view depth (despite the Java image label);
  `gMotion`/`gSpecMotion` = **render-pixel-space vectors**, previous-minus-current, **jitter-free**.
* Motion vectors deliberately subtract the sub-pixel ray jitter (`guides.slang:258, 271-272`) and
  DLSS-RR is *not* told the MVs are jittered (`RtDlssRr.java:35,40-41`).
* There is **no hit-distance guide and no material/geometry-ID guide**. The exact first-bounce ray
  length exists only transiently as `payload.hitT` (`primary.rgen.slang:64`) and is discarded;
  the primary payload is then *overwritten* by the reflection guide probe (`guides.slang:110-118`),
  so by the time `writeGuides()` runs, raygen no longer knows the primary hit's material or hitT.
* `gv_*` state (`guides.slang:16-40`) is the entire interface between `tracePrimary()` and
  `writeGuides()`; adding a signal (hit distance, material ID, PDF) means adding `gv_*` state and
  setting it where `gv_normal`/`gv_hitCamRel` are already set.

## 2. The writer, in full

`guides.slang:236-284`:

```slang
236: public void writeGuides(int2 pix, float3 primaryDir, float2 jndc, float2 size, float primaryConeSpread) {
240:     float2 specMotion = resolveSpecularGuides(
241:             gv_spec, primaryDir, jndc, size, primaryConeSpread, specAlbedo);
247:     float4 curClip = mul(worldPush.curViewProj, float4(gv_hitCamRel, 1.0));
248:     float depth = curClip.w > 0.0 ? curClip.z / curClip.w : 0.0;
...
278:     gNormal[pix]     = float4(gv_normal, gv_rough);
279:     gAlbedo[pix]     = float4(gv_albedo, gv_emissive ? 1.0 : 0.0);
280:     gDepth[pix]      = depth;
281:     gMotion[pix]     = motion;
282:     gSpecAlbedo[pix] = float4(specAlbedo, 1.0);
283:     gSpecMotion[pix] = specMotion;
284: }
```

Call site — the primary pass raygen, after `tracePrimary()` returned and the continuation record
was written (`primary.rgen.slang:247-251`):

```slang
247:     PathSegment terminal = tracePrimary(current, queue, splitRecord, nextRecord);
249:     queue[pixelIndex] = packPathSegment(terminal, nextRecord);
251:     writeGuides(pix, dir, jndc, size, rayConeSpread);
```

`tracePrimary()` sets the `gv_*` state in exactly three places, all gated on `bounce == 0`
(`primary.rgen.slang:76, 138`, plus the miss branch at `49-59`). `writeGuides()` itself never reads
`payload` (it cannot: see §6.1).

## 3. Per-guide specification

### 3.1 `gNormal` — `rgba16f`, written `guides.slang:278`

| | |
|---|---|
| Writer | `gNormal[pix] = float4(gv_normal, gv_rough);` — one line, `guides.slang:278` |
| Pass | **primary only** (`primary.rgen.slang:251`), SBT raygen 0, dispatch 0 at `RtComposite.java:1206` |
| RGB | world-space **shading** normal (unit; normal-mapped / LabPBR-perturbed), oriented toward the viewer (`closest_hit.rchit.slang:367-369` terrain, `277-279` entity, `237-239` particle), water-wave-perturbed when waves are on (`primary.rgen.slang:111-127`). `float3(0,0,0)` for a sky miss (`primary.rgen.slang:51`) |
| A | **linear GGX alpha roughness** (`world_core.slang:36-41`: stored roughness *is* alpha, no squaring). `0.0` for an exact delta mirror (`primary.rgen.slang:69-70`: `rough = exactSpecular ? 0.0 : rough`), `1.0` for particles (`:84`) and sky (`:54`) |
| Encoding | ACEScg has nothing to do with this buffer; no packing — FP16 per channel, `.a` carries roughness (the layout DLSSD's normal guide expects) |
| Jitter | jitter-independent |

Where the value comes from: `gv_normal = payloadNormal(); gv_rough = rough;`
(`primary.rgen.slang:77,90`). `payloadNormal()` is the unpacked half3 from
`Payload.surface1.y/surface2` (`world_core.slang:27`, `world_common.slang:312-319`) — note the
normal therefore travels through **FP16** in the payload before reaching the FP32 guide write
(only the *specular* interface normal was given an FP32 path, see §3.5).

**Transmission replacement (important).** If the primary hit is water/glass, the ordinary tuple is
replaced by the *destination* behind the interface by `setTransmissionGuide()`
(`guides.slang:148-157`, called from `resolveTransmissionGuide()` `guides.slang:161-233`), which
overwrites `gv_normal`, `gv_rough`, `gv_albedo`, `gv_hitCamRel`, `gv_motionObjDisp` with the
destination's attributes. So for a water pixel `gNormal` describes what is *behind* the water, not
the water surface (the water interface lives in `gSpec*`). The destination roughness is **not**
delta-snapped there: `endpointRoughness = clamp(payloadRoughness(), 0.0, 1.0)` (`guides.slang:185`),
vs. the snap applied at `primary.rgen.slang:69-70`.

### 3.2 `gAlbedo` — `rgba16f`, written `guides.slang:279`

| | |
|---|---|
| Writer | `gAlbedo[pix] = float4(gv_albedo, gv_emissive ? 1.0 : 0.0);` — `guides.slang:279` |
| RGB | **diffuse albedo**, linear **ACEScg** (AP1/D60) — the tracer's transport basis (`world_common.slang:334-348`, conversion applied in the hit shader at `closest_hit.rchit.slang:243,301,405`). For non-dielectric hits it is demodulated: `diffAlb = hitAlbedo * (1.0 - metal)` (`primary.rgen.slang:71-75`); particles use raw albedo (`:82-83`); sky uses `SKY_DIFF_ALBEDO = (0.5,0.5,0.5)` (`primary.rgen.slang:52`, constant at `world_core.slang:67`) |
| A | **not a DLSS-RR input** — the emissive flag (`0.0`/`1.0`) kept for exposure metering, explicitly documented `guides.slang:18-21`; consumed at `exposure_hist/main.comp.slang:53` and `debug_present/main.comp.slang:97` |
| Jitter | jitter-independent |

Transmission case: `gv_albedo = guideFilter * endpointAlbedo` of the destination
(`guides.slang:186-192`), where `guideFilter` starts at `1.0` and is multiplied by the entering
dielectric's albedo for non-water glass (`guides.slang:158-159, 221-223`), or
`guideFilter * SKY_DIFF_ALBEDO` on the escape-to-sky branch (`guides.slang:175-177`).

### 3.3 `gDepth` — `r32f`, written `guides.slang:280`

| | |
|---|---|
| Writer | computed `guides.slang:247-248`, stored `guides.slang:280` |
| Meaning | **hardware (non-linear) reversed-Z depth** `ndc.z / ndc.w` of the guide point, produced by the *forward, unjittered* matrix `worldPush.curViewProj` (`guides.slang:247`, matrix filled at `RtComposite.java:1006,1144` = `frameProjection * frameViewRotation`) |
| Encoding | `z/w`, near = 1, far = 0 → DLSS gets `DepthInverted` (`RtDlssRr.java:38,41`); sky/1e6 hit → ~0 |
| Guard | `curClip.w > 0.0 ? ... : 0.0` (`guides.slang:248`) |
| Jitter | **jitter-free**: the matrix carries no jitter (jitter is applied in NDC only, `primary.rgen.slang:225`), and projecting the hit point is independent of which ray found it |

Exact source comment (`guides.slang:243-246`):

```slang
243:     // Hardware (non-linear, reversed-Z) depth for DLSS-RR + Frame Generation: project the camera-relative
244:     // primary hit through the forward view-projection and take ndc z/w — exactly the value a rasterizer
245:     // would write. Reversed-Z (near=1, far=0), so DLSS gets the DepthInverted flag; sky's far hit -> ~0.
246:     // Clear transmission uses destination depth so the entire ordinary tuple describes one layer.
```

The **Java image label is wrong** ("guide linear depth", `RtComposite.java:967`); the value is HW
depth. Anything reconstructing linear depth from it must use the reversed-Z formula with
`frameProjection * frameViewRotation`.

Value fed in: `gv_hitCamRel` (`guides.slang:23`), set at `primary.rgen.slang:55` (`rd * 1.0e6` on a
miss), `:78` (opaque/particle hit), `:143` (dielectric interface itself), or replaced by the
destination in `setTransmissionGuide` (`guides.slang:150`).

### 3.4 `gMotion` — `rg16f`, written `guides.slang:281` (computed `guides.slang:250-275`)

```slang
256:     float4 prevClip = mul(worldPush.prevViewProj,
257:             float4(gv_hitCamRel + worldPush.camDelta - gv_motionObjDisp, 1.0));
258:     float2 curNdc = jndc; // primary hit's current screen position is exactly the jittered ray ndc
...
270:     if (prevClip.w > 0.0 && (!gv_motionUseRefracted || curClipMotion.w > 0.0)) {
271:         if (gv_motionUseRefracted) curNdc = curClipMotion.xy / curClipMotion.w;
272:         motion = (prevClip.xy / prevClip.w - curNdc) * 0.5 * size;
273:     } else {
274:         motion = float2(0.0, 0.0);
275:     }
```

| | |
|---|---|
| Units | **render-pixel space**: NDC delta × `0.5 * size` where `size = float2(DispatchRaysDimensions())` = render resolution (`primary.rgen.slang:223,251`); DLSS is told `MVLowRes` + scale 1.0 (`RtDlssRr.java:37,41,112`) |
| Direction | previous − current (NVIDIA sample-code convention) |
| Inputs | guide point camera-relative (`gv_hitCamRel`), previous-frame camera matrix `prevViewProj`, camera translation `camDelta`, and the hit's own world displacement `gv_motionObjDisp` (per-vertex/object motion, subtracted to de-camera the MV — `guides.slang:254-255`) |
| Guards | a guide point behind either camera yields exactly `(0,0)` rather than a garbage divide (`guides.slang:264-275`) |
| Jitter | **jitter is subtracted**: `curNdc = jndc` (`guides.slang:258`) where `jndc` is the jittered ray NDC (`primary.rgen.slang:225`). Because the hit lies exactly on the jittered ray, projecting it with `curViewProj` reproduces `jndc`, so a static surface gives bit-exact `(0,0)` — including on the first frame after a resize, where `prevViewProj == curViewProj` and `camDelta == 0` (`RtComposite.java:975,1012-1017`) |

For transmission-replaced pixels (`gv_motionUseRefracted == true`, `guides.slang:152`) the current
position is recomputed from the *destination's* own projection (`guides.slang:261-263,271`), which is
why the guard checks both `w`s.

### 3.5 `gSpecAlbedo` — `rgba16f`, written `guides.slang:282`

| | |
|---|---|
| Writer | `gSpecAlbedo[pix] = float4(specAlbedo, 1.0);` — `guides.slang:282`; `specAlbedo` produced by `resolveSpecularGuides()` (`guides.slang:94-146`, called `guides.slang:240-241`) |
| RGB | DLSS-RR **specular albedo** = integrated/view-dependent specular reflectivity, *not* raw F0. Opaque/entity hit: `rrSpecularAlbedo(payload.f0, rough, dot(n, v))` (`primary.rgen.slang:91-92`; fit at `math.slang:48-79`). Dielectric interface: `float3(F,F,F)` from Fresnel (`primary.rgen.slang:146-148`). Particles: `(0,0,0)` (`primary.rgen.slang:85-86`). Sky: `SKY_SPEC_ALBEDO = (0.5,0.5,0.5)` (`primary.rgen.slang:58`, `world_core.slang:66`) |
| RGB (mirror case) | for near-mirrors (`roughness <= MIRROR_ALPHA_MAX`) whose reflected hit is opaque/particle and non-emissive, the foreground albedo is multiplied by the reflected surface's diffuse albedo (`guides.slang:123-134`), giving RR a demodulation signal for a sharp reflection |
| A | hardcoded `1.0`; unused by this repo (debug pass reads only `.rgb`, `debug_present/main.comp.slang:109`) |
| Jitter | jitter-independent |
| Colour space | ACEScg scene-linear (same basis as `gAlbedo`) |

Crucially `specAlbedo` is written **even when the reflection motion is gated off**: the early-out at
`guides.slang:98-102` returns `(0,0)` motion but leaves `specAlbedo = surface.albedo`
(assigned at `guides.slang:97`, before the test).

### 3.6 `gSpecMotion` — `rg16f`, written `guides.slang:283`

Produced by `resolveSpecularGuides()` (`guides.slang:94-146`); this function also performs the one
reflection guide probe:

```slang
110:     traceGuide(CULL_SECONDARY,
111:             offsetSurfaceOrigin(surfacePos, surface.biasNormal, specDir, SURF_BIAS),
112:             RAY_TMIN, specDir, 10000.0,
113:             max(length(surface.camRel) * primaryConeSpread, RAY_CONE_MIN_WIDTH),
114:             max(primaryConeSpread, RAY_CONE_MIN_SPREAD));
...
117:     if (payload.hitT > 0.0) { reflectedHit = surfacePos + specDir * payload.hitT; ... }
...
142:     float2 prevNdc = previousReflectionNdc(
143:             surfacePos, previousN, surface.motionPrev, reflectedHit, reflectedMotionPrev, prevValid);
145:     return prevValid ? (prevNdc - currentNdc) * 0.5 * size : float2(0.0, 0.0);
```

| | |
|---|---|
| Meaning | **reflection motion vector**: previous-frame screen position of the *mirrored* image of the reflected terminal, minus the current pixel NDC |
| Method | `previousReflectionNdc()` (`guides.slang:80-87`) mirrors the reflected hit across the reflector plane in world space (`mirroredHit = prevHit - 2 n (prevHit - prevSurfacePos)·n`) and projects it with `prevViewProj` via `projectPrevNdc()` (`guides.slang:67-71`). Mirroring is division-free specifically so static mirrors give bit-exact zero MV (comment `guides.slang:73-79`) |
| Units | render pixels (`* 0.5 * size`, `guides.slang:145`) |
| Gated to zero when | `\|normal\| < 0.5` (sky/TIR), `max(albedo) <= 0.001` (particles), or `roughness > SPEC_MOTION_ALPHA_MAX = 0.25` (`guides.slang:98-102`, constant `world_core.slang:90`) — i.e. only smooth-to-medium lobes get a reflection MV; broad glossy falls back to `gMotion` |
| Reflector motion | `surface.motionPrev` (reflector's own displacement) and `reflectedMotionPrev` (the reflected content's displacement from `payload.motionPrev`, `guides.slang:122`) |
| Jitter | **subtracted**: `currentNdc = jndc` is passed in from `writeGuides` (`guides.slang:240-241`, `251`), so the delta is jitter-free |
| Miss case | reflected hit placed at `surfacePos + specDir * 1.0e6` with zero content motion (`guides.slang:135-138`) |

The reflection probe is a **single deterministic mirror ray** (`specDir = reflect(primaryDir, n)`,
`guides.slang:106`), traced with `CULL_SECONDARY` (excludes particles, includes the player;
`lighting.slang:323-326`), tmax `10000.0`, cone derived from the pixel footprint and hit distance
(`guides.slang:112-114`). That probe **overwrites the module-level `payload`** (`trace.slang:72-77`)
— see §6.1.

## 4. Q4 — first-bounce hit distance / ray length

**It is computed, then thrown away.**

* The primary ray is emitted with unit direction (`primary.rgen.slang:231`
  `float3 dir = normalize(farP - nearP);`) and the ordinary radiance trace at
  `primary.rgen.slang:46-47`. `RayTCurrent()` becomes `payload.hitT` in the closest-hit shader
  (`closest_hit.rchit.slang:245` particle, `:309` entity, `:390` dielectric, `:407` terrain), so
  **`payload.hitT` at `primary.rgen.slang:64` *is* the first-bounce ray length in blocks**:

  ```slang
  63:         float3 n = payloadNormal();
  64:         float3 hitPos = ro + rd * payload.hitT;
  ```

  It is used for the hit position, for Beer–Lambert attenuation (`primary.rgen.slang:101-103`) and
  for ray-cone growth (`:104-105`), and is never copied into `gv_*`.
* The only surviving proxy is the hit *position* `gv_hitCamRel` (`primary.rgen.slang:78`), written
  to no guide either — it is consumed by the depth/motion math (`guides.slang:247,257`). Since
  `gv_hitCamRel = hitPos - camOffset` and the ray origin is `nearP + camOffset`
  (`primary.rgen.slang:230`), `length(gv_hitCamRel)` is the distance from the camera-relative
  origin, i.e. ≈ `hitT + nearDistance` (exactly `hitT` only when the effective eye is the origin;
  the eye is *not* the origin by design — `primary.rgen.slang:8-12`). So it is a usable but not
  exact hit distance.
* For the **specular** probe the ray length is available too and also discarded: `payload.hitT` at
  `guides.slang:117-118` (`reflectedHit = surfacePos + specDir * payload.hitT;`) is the reflection
  probe's hit distance measured from the biased origin.
* The diffuse *first moment* (path throughput × hit distance, ReBLUR/ReLAX style) is **not computed
  anywhere**. Pass A does no BSDF sampling at all (`primary.rgen.slang:5-6`); the only BSDF
  sampling lives in the indirect pass (`indirect.rgen.slang:353-386`), which writes no guides.

**Could it be written out cheaply?** Yes — the value already exists in a register at the exact place
the other `gv_*` fields are set:

1. Add `public static float gv_hitDist;` to the guide state block (`guides.slang:16-40`) and set it
   alongside `gv_hitCamRel` (`primary.rgen.slang:55` miss → sentinel like `1.0e6`; `:78` hit →
   `payload.hitT`; `:143` interface → `payload.hitT`), plus in `setTransmissionGuide()`
   (`guides.slang:148-157`) for the transmission-replaced tuple if the destination distance is
   wanted (currently the crossing loop knows `payload.hitT` at `guides.slang:182`).
2. Store it in `writeGuides()`. Zero new traversal cost, one extra static register, one extra
   store, and — if no new image is desired — it can ride in an unused lane: `gSpecAlbedo.a` is
   hardcoded `1.0` and read by nothing in this repo (`guides.slang:282`,
   `debug_present/main.comp.slang:109`). A dedicated `r16f`/`r32f` image would be the honest
   option for an external denoiser, since DLSSD's guide set is fixed at six images
   (`RtDlssRr.java:80-113`).
3. If a *first moment* (distance-weighted radiance) is needed, it must be accumulated in the
   indirect pass instead, because that is the only place radiance is accumulated
   (`indirect.rgen.slang:37-398`) — pass A contributes no radiance term to `outImage`
   (only pass B's `outImage[pix] = ...`, `indirect.rgen.slang:435`).

## 5. Q5 — roughness / material ID / specular ray origin & PDF at the write site

At `writeGuides()` (`guides.slang:236-284`) the live state is exactly the `gv_*` block
(`guides.slang:16-40`) plus `worldPush`:

| Signal | Available at `writeGuides`? | Where |
|---|---|---|
| Ordinary roughness | **Yes** | `gv_rough` (`guides.slang:22`), set at `primary.rgen.slang:84,90`, `:140`, `guides.slang:154`, `:185` — already written to `gNormal.a` at `guides.slang:278` |
| Specular/interface roughness | **Yes** | `gv_spec.roughness` (`guides.slang:37`), set at `primary.rgen.slang:85,91,146`; used by the gate at `guides.slang:100` |
| Primary material | **No** | The primary `payload` is gone: `resolveSpecularGuides()` (`guides.slang:240-241`) already re-traced a guide ray (`guides.slang:110-114`) into the module-level `payload` (`world_core.slang:14`, `trace.slang:74`). `payloadMaterial()` (`world_core.slang:31`) at that point returns the *reflection probe's* material, not the primary hit's |
| Coarse material class | Only indirectly | What survived is the branch taken: `gv_emissive` (`guides.slang:21`) and the albedo/roughness values. The 2-bit class itself would have to be re-captured |
| MaterialHeader / per-prim `materialId` | **No** | Live only inside the hit shader: `TerrainPrim.materialId` (`closest_hit.rchit.slang:336`, struct `world_common.slang:219-226`), `Prim.materialId` (`closest_hit.rchit.slang:296`), looked up in `pc.materialTableAddr`; never placed in the payload |
| Specular ray origin | **Yes, but local** | `specDir` and the origin `offsetSurfaceOrigin(surfacePos, surface.biasNormal, specDir, SURF_BIAS)` (`guides.slang:106,111`); `surfacePos = surface.camRel + worldPush.camOffset` (`guides.slang:104`) |
| Specular lobe PDF | **Does not exist** | The probe is one deterministic mirror direction with hardcoded tmax/cone; there is no BSDF sampling, no pdf, no MIS anywhere in pass A. The GGX lobe sampling and its probability `ps` exist only in pass B (`indirect.rgen.slang:355-357, 366-374`), which imports no guides (`indirect.rgen.slang:2-6, 21-33`) |
| Specular hit distance | **Yes, transiently** | `payload.hitT` at `guides.slang:117-118`, discarded immediately |
| Surface displacement | **Yes** | `gv_motionObjDisp` (`guides.slang:27`) and `gv_spec.motionPrev` / `previousNormal` (`guides.slang:34,36`) |

So roughness is free; **material ID and specular PDF require new plumbing** (a `gv_*` field set in
`tracePrimary()`, or a new payload lane written in the hit shader), and the specular ray
origin/hit-distance is free to capture inside `resolveSpecularGuides()`.

## 6. Q6 — sub-pixel jitter: generation, application, propagation

1. **Generation** — `CausticaJitter.prepare(renderW, renderH, displayW)`
   (`CausticaJitter.java:22-27`): Halton(2,3) minus 0.5, phase index advanced per frame with
   `phaseCount = max(32, ceil(8 * (display/render)^2))` (`CausticaJitter.java:38-41`), i.e. the DLSS
   phase-count rule with RR's floor of 32. Signed in render pixels, values in `[-0.5, +0.5)`.
2. **Sign / storage** — `RtComposite.java:1047-1051`:
   ```java
   1047:  if (rrPath) {
   1048:      CausticaJitter.INSTANCE.prepare(renderW, renderH, displayW);
   1049:      jitterX = CausticaJitter.INSTANCE.jitterPixelsX() * jitterSignX();
   1050:      jitterY = CausticaJitter.INSTANCE.jitterPixelsY() * jitterSignY();
   1051:  }
   ```
   `jitterSignX` default `1.0`, `jitterSignY` default `-1.0` (Vulkan flipped clip space)
   — `RtComposite.java:137-145`, `CausticaConfig.java:542-545`. With RR off, jitter stays `0`
   (`RtComposite.java:1045-1046`).
3. **Push to the GPU** — written into `WorldPush.jitter` (`world_common.slang:55`) as
   `new Float2(jitterX, jitterY)` at `RtComposite.java:1132`, ring-buffer slot flushed at
   `RtComposite.java:1161`.
4. **Applied to raygen** — *one* place in all shaders (a repo-wide grep for `worldPush.jitter`
   returns only this line):
   ```slang
   224:     float2 uv = (float2(pix) + 0.5) / size;
   225:     float2 jndc = (uv + worldPush.jitter / size) * 2.0 - 1.0;
   ```
   `primary.rgen.slang:224-225`. `jndc` then drives `invViewProj` unprojection (`:226-231`), the ray
   cone (`:232`), and is forwarded to `writeGuides(pix, dir, jndc, size, rayConeSpread)` at `:251`.
   The matrices themselves (`invViewProj`, `curViewProj`, `prevViewProj`) are **jitter-free**
   (`RtComposite.java:1006,1062`; comment `RtComposite.java:510`), so the jitter is purely an NDC
   offset of the ray direction.
5. **Guides** — `jndc` is used as the "current screen position" when building the MVs, which is how
   the jitter is removed: `guides.slang:258` (`float2 curNdc = jndc;`) and `:271-272`; the specular
   MV uses the same subtraction (`guides.slang:145` with `currentNdc = jndc` passed from `:240-241`).
   Depth uses `curViewProj` on the hit position (`guides.slang:247`), so it carries no jitter either.
6. **Reported to DLSS** — `RtComposite.java:1219-1221` passes **negated** values:
   `-jitterX, -jitterY` (with the comment that MVs are already render-pixel units, so MV scale = 1;
   `RtDlssRr.java:111-112`). `MV_JITTERED` is deliberately not set (`RtDlssRr.java:35,40-41`),
   consistent with the MVs being jitter-free.
7. **Indirect pass** — never sees the jitter; it resumes the queued `PackedPathSegment`s
   (`indirect.rgen.slang:402-421`) whose origins/directions were baked in pass A
   (`segment.slang:109-125`).

## 7. Q7 — existing material / geometry ID buffer?

**No.** There is no ID guide, no primitive/section ID image, and no debug view for one:

* The complete per-pixel G-buffer surface is the six images in `bindings.slang:11-16`, and a
  repo-wide grep shows they are written only at `guides.slang:278-283` and read only by
  `debug_present/main.comp.slang:89-113` plus the exposure histogram
  (`exposure_hist/main.comp.slang:48-53`).
* The exposed debug views are 1..9 (normals, albedo, depth, roughness, motion, specular,
  specular motion, exposure false colour, metering weight) — `en_us.json:52-61`,
  `debug_present/main.comp.slang:91-113`. No ID/primitive view.
* Identifiers do exist in device memory, but only *inside* hit shaders:
  * `TerrainPrim.materialId` / `Prim.materialId` (`world_common.slang:222,211`) → `MaterialHeader`
    via `pc.materialTableAddr` (`closest_hit.rchit.slang:336,296`);
  * `InstanceID()`, `PrimitiveIndex()`, `GeometryIndex()` and the section/entity tables
    (`closest_hit.rchit.slang:217-220, 262-266, 329-334`; `Section` at `world_common.slang:260-264`,
    `EntityGeom` at `:268-276`; TLAS custom-index encoding `ENTITY_BIT`/`PARTICLE_BIT`/`IDX_MASK`
    at `:279-284`);
  * `MaterialHeader.model` (the 2-bit `MATERIAL_*` class, `world_common.slang:196-205`).
* Raygen only ever receives the **2-bit material class**, packed into `Payload.flags` bits 0..1
  (`world_common.slang:171`; `payloadSetPacked()` `closest_hit.rchit.slang:13-19`;
  `payloadMaterial()` `world_core.slang:31`). Bits 2 (celestial), 3 (dielectric entering),
  4..6 (emission source), 7 (emitter-in-list) are taken (`world_common.slang:178-194`); **bits 8..31
  are unused**, so a coarse material/geometry ID could ride in `flags` without growing the payload —
  the payload is explicitly register/latency-sensitive (`world_common.slang:142-148`,
  `trace_ser.slang:13-19`).

So a material/geometry ID guide must either (a) be written into a spare `Payload.flags` bit-field or
an added payload word in `closest_hit.rchit.slang` and copied into `gv_*` where
`payloadMaterial()` is already called (`primary.rgen.slang:65`), or (b) be re-derived by re-tracing
the primary ray in a separate ID pass — which duplicates the primary traversal and is the only
option that cannot work at all without touching the payload ABI, because raygen has no
instance/primitive identity.

## 8. Cross-cutting facts and gotchas worth knowing before extending this

1. **`gv_*` are module-level `static` globals** (`guides.slang:16-40`), used as an
   implicit register-passing channel from `tracePrimary()` to `writeGuides()`. Adding a guide signal
   = adding a global; there is no struct.
2. **The primary payload is destroyed before guides are written.** `resolveSpecularGuides()`
   (`guides.slang:110-114`) traces through the same module-level `payload` (`world_core.slang:14`),
   so `payloadMaterial()`, `payloadRoughness()`, `payload.hitT`, `payload.motionPrev` etc. inside
   `writeGuides()` all refer to the *reflection probe* result, not the primary hit. Any new guide
   derived from the primary payload must be captured inside `tracePrimary()`.
3. **Guide miss sentinel.** `makeRadiancePayload()` seeds `hitT = -1.0` (`trace.slang:46`); the guide
   miss record (`guide.rmiss.slang:7-12`) deliberately preserves `hitT` (it only clears
   `flags`/normal), so `if (payload.hitT > 0.0)` at `guides.slang:117` is a reliable hit test, and
   guide probes never march the atmosphere (the radiance miss is `sky.rmiss`, `RtComposite.java:722`,
   `trace.slang:16-17`).
4. **Transmission is a whole-tuple replacement, not a separate layer.** For water/glass the ordinary
   guides describe the destination (1..N crossings of the deterministic
   `resolveTransmissionGuide()` loop, `guides.slang:161-233`), while the *interface* is preserved
   only in `gv_spec` (`guides.slang:28-30, 148-157`). The loop is capped by
   `worldPush.maxBounces` (`guides.slang:171`) and can bail out on TIR with a zeroed specular-ish
   tuple (`guides.slang:214-220`).
5. **Precision funnel.** Everything the guides are built from passes through the `Payload`
   (`world_common.slang:149-176`): albedo, normal, F0 and per-vertex motion are **FP16**
   (`half3`), roughness/metalness/emission/IOR/transmission are packed half2, and only `hitT`,
   sky radiance and the hand-packed surface words keep FP32. The normal guide is therefore FP16-sourced
   even though the guide image is `rgba16f`; the specular interface normal was specifically kept
   "FP32" in the `SpecSurface` struct (`guides.slang:33`) only in the sense that it is not
   re-quantized after `payloadNormal()`.
6. **MV convention sanity.** Both MVs are `(previous − current)` in render pixels, matching the
   NVIDIA sample-code convention; `MVLowRes` is set and the MV scale passed to NGX is 1.0
   (`RtDlssRr.java:37,112`). First frame after resource recreation: `prevViewProj == curViewProj`,
   `camDelta == 0` (`RtComposite.java:975,1012-1017`), and because the guide point lies on the
   jittered ray, `prevClip.xy/w == jndc` → exactly `(0,0)` MVs, as the comment claims.
7. **`gDepth` is HW depth, not linear depth** (label at `RtComposite.java:967` vs. writer
   `guides.slang:247-248`); sky pixels are ~0 because the miss branch sets
   `gv_hitCamRel = rd * 1.0e6` (`primary.rgen.slang:55`), not because of an explicit clear.
8. **Sky guide tuple**: normal `(0,0,0)`, roughness `1.0`, diffuse albedo `0.5` grey, emissive flag
   `false`, specular albedo `0.5` grey, specular motion `0` (gated by `|normal| < 0.5`)
   — `primary.rgen.slang:51-58`, `guides.slang:98-102`.
9. **`gAlbedo.a` is the only guide lane DLSS-RR does not consume**; it is a metering signal
   (`guides.slang:18-21`, `exposure_hist/main.comp.slang:53`). `gSpecAlbedo.a` is a constant `1.0`
   and is consumed by nobody in this repo (`guides.slang:282`,
   `debug_present/main.comp.slang:109`) — the most obvious spare lane for a small extra signal.
